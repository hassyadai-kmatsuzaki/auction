## 1. 事前指値 → お気に入り自動追加

### 概要

事前指値（上限価格）を設定した商品を自動的にお気に入りに追加する。
指値を解除した場合はお気に入りからも自動的に解除する。

### 現状

- 指値設定とお気に入りは完全に独立した機能
- 指値は `bid_limit_prices` テーブル、お気に入りは `favorites` テーブルで管理
- 指値を設定してもお気に入りには反映されない

### 変更内容

#### バックエンド

**対象ファイル:** `app/Actions/Bid/SetBidLimitAction.php`

- 指値設定時（`execute` メソッド内）に、`favorites` テーブルへの登録を追加
- 既にお気に入り登録済みの場合はスキップ（重複防止）

```
処理フロー:
1. 指値を保存（既存処理）
2. favorites テーブルに該当 item_id + user_id が存在しなければ INSERT
3. 既存の指値チェック処理を続行（既存処理）
```

**対象ファイル:** `app/Http/Controllers/Participant/BidLimitController.php`

- 指値削除時（`destroy` メソッド内）に、`favorites` テーブルからも該当レコードを削除

```
処理フロー:
1. bid_limit_prices から該当レコードを削除（既存処理）
2. favorites テーブルから該当 item_id + user_id のレコードを削除
```

#### フロントエンド

**対象ファイル:** `resources/ts/pages/participant/AuctionItems.tsx`

- 指値設定後に `favoriteIds` のローカルステートも更新（UIの即時反映）
- `handleSetLimit` 成功時に `favoriteIds` に item_id を追加
- `handleRemoveLimit` 成功時に `favoriteIds` から item_id を削除

**対象ファイル:** `resources/ts/pages/participant/Favorites.tsx`

- 指値解除時にお気に入りリストからも該当アイテムを除外するUIフロー
- `handleRemoveLimit` 成功時に `favorites` ステートからも該当アイテムを除外

### バリデーション・考慮事項

- 手動でお気に入りに追加した商品は、指値を設定していなくてもお気に入りに残る
- 指値解除時のお気に入り削除は、指値経由で追加されたものだけでなく、手動追加分も含めて削除する（指値解除 = 興味がなくなった、と解釈）
- お気に入りを手動で解除しても指値は残る（指値はセーフティ機能のため独立して維持）

## 2. オークション開催ページ - 次の商品表示

### 概要

ライブオークション画面（`AuctionLive.tsx`）で、現在競り中の6レーンの下部に、各レーンの次に来る商品を簡易的に表示する。

### 現状

- ライブ画面では6レーンの現在の商品のみ表示
- 次に来る商品の情報は参加者には見えない
- 出品一覧ページ（`AuctionItems.tsx`）に遷移すれば確認可能

### 変更内容

#### バックエンド

**対象ファイル:** `app/Http/Controllers/Admin/LiveController.php`（または該当するライブ状態API）

- `getLiveState` レスポンスに各レーンの `upcoming_items` を追加
- 各レーンの次の商品（2〜3件程度）の簡易情報を含める

```json
{
  "lanes": [
    {
      "lane_id": 1,
      "current_item": { ... },
      "upcoming_items": [
        {
          "id": 101,
          "item_number": 5,
          "species_name": "幹之メダカ",
          "quantity": 3,
          "start_price": 2000,
          "thumbnail_path": "/path/to/thumb.jpg",
          "is_premium": false
        },
        {
          "id": 102,
          "item_number": 6,
          "species_name": "楊貴妃メダカ",
          "quantity": 5,
          "start_price": 1500,
          "thumbnail_path": null,
          "is_premium": true
        }
      ]
    }
  ]
}
```

- `upcoming_items` は `lane_items` テーブルの `sequence_order` で現在の商品より後のものを取得
- 最大3件まで

#### フロントエンド

**対象ファイル:** `resources/ts/pages/participant/AuctionLive.tsx`

- レーングリッドの下部に「次の商品」セクションを追加

```
レイアウト:
┌──────────────────────────────────────────┐
│  [レーン1] [レーン2] [レーン3]            │  ← 現在の6レーン
│  [レーン4] [レーン5] [レーン6]            │
├──────────────────────────────────────────┤
│  📋 次の商品                              │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ...    │
│  │サムネ│ │サムネ│ │サムネ│ │サムネ│        │
│  │品種名│ │品種名│ │品種名│ │品種名│        │
│  │¥開始 │ │¥開始 │ │¥開始 │ │¥開始 │        │
│  └─────┘ └─────┘ └─────┘ └─────┘        │
└──────────────────────────────────────────┘
```

**新規コンポーネント:** `resources/ts/features/auction-live/components/UpcomingItems.tsx`

- 各レーンの `upcoming_items` をフラットにまとめて横スクロール or グリッド表示
- 各アイテムは簡易カード（サムネイル + 品種名 + 開始価格 + 匹数）
- プレミアムバッジ表示
- レーン番号のラベル付き（どのレーンの次の商品かわかるように）

**対象型定義:** `resources/ts/types/index.ts`

- `LiveLane` 型に `upcoming_items` フィールドを追加

### 考慮事項

- 次の商品情報は WebSocket のリアルタイム更新ではなく、`getLiveState` のポーリング時に更新
- レーンの商品が進行した場合は `LaneChanged` イベント後の `refetch` で自動更新
- 全レーンの次の商品が0件の場合はセクション自体を非表示

## 3. ホームページ - 開催中・次回開催の表示改善

### 概要

ホームページ（`Home.tsx`）で、開催中オークションと次回開催予定をページ最上部に全幅で目立たせて表示する。お知らせよりも上に配置する。

### 現状

- 開催中: 小さな `Alert` バー（success severity）
- 次回開催: ページ下部の `Card`
- お知らせが最も目立つ位置にある

### 変更内容

**対象ファイル:** `resources/ts/pages/participant/Home.tsx`

#### 表示順序の変更

```
変更前:
1. 開催中Alert
2. お知らせ
3. 広告
4. 次回開催予定

変更後:
1. 開催中バナー（全幅・大型）
2. 次回開催カード（全幅・目立つデザイン）
3. お知らせ
4. 広告
```

#### 開催中オークションの表示（大型バナー）

```
┌──────────────────────────────────────────────┐
│  🔴 LIVE  オークション開催中！                 │
│                                                │
│  第15回 メダカライブオークション                │
│                                                │
│  [  今すぐ参加する  →  ]                       │
│                                                │
│  120点出品 ・ 参加者 85名                       │
└──────────────────────────────────────────────┘
```

- 背景: グラデーション（primary系）またはアクセントカラー
- アニメーション: 「LIVE」ラベルに点滅効果
- 全幅表示（Container の外に出す or maxWidth を解除）
- ボタンは大きく目立つデザイン

#### 次回開催予定の表示

```
┌──────────────────────────────────────────────┐
│  📅 次回開催予定                               │
│                                                │
│  第16回 メダカライブオークション                │

- 開催日までのカウントダウン表示（あと○日）
- 開催中がない場合は、次回開催をさらに大きく表示

#### 開催中も次回開催もない場合

```

│  現在開催中のオークションはありません            │

└──────────────────────────────────────────────┘

### 考慮事項

- スマートフォンでも見やすいレスポンシブデザイン
- 開催中バナーは目を引くが、うるさくなりすぎないバランス
- カウントダウンは日単位（当日になったら「本日開催」と表示）

### 6-3. カスタム設定ONでデフォルト値を初期値として設定

#### 概要

カスタム設定トグルをONにした際に、システムデフォルト値を各フィールドの初期値として自動設定する。

#### 現状

- カスタム設定をONにしても、フォームの値は `DEFAULT_FORM_DATA` のハードコードされた値のまま
- システム設定画面で変更したデフォルト値が反映されない

#### 変更内容

**対象ファイル:** `resources/ts/pages/admin/AuctionForm.tsx`

- `use_custom_settings` トグルをONにした際に、APIから取得した `defaults` データを各カスタム設定フィールドに反映する

```typescript
onChange={(e) => {
  const useCustom = e.target.checked;
  setAuction({ use_custom_settings: useCustom });
  if (useCustom && defaults) {
    setCustomAuction({
      price_increment_rate: defaults.auction_settings.price_increment_rate,
      price_increment_min: defaults.auction_settings.price_increment_min,
      countdown_seconds_default: defaults.auction_settings.countdown_seconds_default,
      countdown_seconds_competitive: defaults.auction_settings.countdown_seconds_competitive,
      venue_open_minutes_before_start: defaults.auction_settings.venue_open_minutes_before_start,
      item_switch_delay_seconds: defaults.auction_settings.item_switch_delay_seconds,
    });
    setCustomFee({ ...defaults.fee_settings });
    setCustomShipping({ ...defaults.shipping_settings });
  }
}}
```

- 既に編集中（既存オークションの編集時）で、既にカスタム値が設定されている場合は上書きしない
- 新規作成時のみデフォルト値を自動設定

### 6-4. カスタム設定ヘルプテキスト修正

### 7-2. 画像の一括アップロード（ZIPファイル対応）

#### 概要

生体管理画面で、ZIPファイルにまとめた画像を一括アップロードし、ファイル名で生体と紐付ける機能を追加する。

#### 現状

- 画像アップロードは生体編集画面（`ItemForm.tsx`）で1件ずつ行う
- CSVインポートは生体情報（テキストデータ）のみ対応
- 一括での画像アップロード機能はない

#### 変更内容

##### バックエンド

**新規ファイル:** `app/Http/Controllers/Admin/ItemMediaBulkController.php`

```
POST /api/admin/auctions/{auctionId}/items/media/bulk-upload
```

- ZIPファイルを受け取り、展開
- ファイル名の命名規則で生体と紐付け

**ファイル命名規則:**

```
{生体番号}_{連番}.{拡張子}

例:
001_1.jpg  → 生体番号1の1枚目
001_2.jpg  → 生体番号1の2枚目
002_1.jpg  → 生体番号2の1枚目
003_1.png  → 生体番号3の1枚目
```

- 生体番号（item_number）でマッチング
- 各生体の最初の画像（_1）を自動的にサムネイルに設定
- 対応フォーマット: jpg, jpeg, png, gif, webp
- ZIPファイルサイズ上限: 500MB
- 1ファイルあたりの上限: 10MB

**レスポンス:**

```json
{
  "success": true,
  "data": {
    "total_files": 50,
    "uploaded": 48,
    "skipped": 2,
    "errors": [
      "ファイル 'unknown_1.jpg' に対応する生体番号が見つかりません",
      "ファイル '003_5.jpg' のサイズが上限を超えています"
    ],
    "results": [
      { "item_number": 1, "uploaded_count": 3 },
      { "item_number": 2, "uploaded_count": 2 }
    ]
  }
}
```

**処理フロー:**

```
1. ZIPファイルを受信
2. 一時ディレクトリに展開
3. ファイル名をパースして生体番号を取得
4. 該当オークションの生体番号と照合
5. マッチした画像を item_media テーブルに登録 & ストレージにアップロード
6. 各生体の最初の画像をサムネイルに設定（既存サムネイルがない場合のみ）
7. 結果レポートを返却
8. 一時ファイルをクリーンアップ
```

##### フロントエンド

**対象ファイル:** `resources/ts/pages/admin/ItemManagement.tsx`

- ヘッダーのボタン群に「画像一括アップロード」ボタンを追加
- ZIPアップロード用のダイアログを追加

**新規ダイアログ:**

```
┌──────────────────────────────────────────────┐
│  🖼️ 画像一括アップロード                       │
├──────────────────────────────────────────────┤
│                                                │
│  ℹ️ ZIPファイルに画像をまとめてアップロード     │
│     できます。                                 │
│                                                │
│  📋 ファイル命名規則:                          │
│     {生体番号}_{連番}.jpg                      │
│     例: 001_1.jpg, 001_2.jpg, 002_1.jpg       │
│                                                │
│  ┌────────────────────────────────────────┐   │
│  │                                        │   │
│  │   クリックしてZIPファイルを選択         │   │
│  │   または、ファイルをドラッグ&ドロップ    │   │
│  │                                        │   │
│  └────────────────────────────────────────┘   │
│                                                │
│  ⚠️ 最大500MB / 対応: jpg, png, gif, webp     │
│                                                │
│  {アップロード結果表示エリア}                   │
│                                                │
│            [閉じる]  [アップロード]             │
└──────────────────────────────────────────────┘
```

- アップロード中はプログレスバーを表示
- 完了後に結果サマリー（成功件数・スキップ件数・エラー一覧）を表示
- アップロード成功後に生体一覧を自動リフレッシュ

##### ルーティング

**対象ファイル:** `routes/api.php`

```php
Route::post('admin/auctions/{auctionId}/items/media/bulk-upload', [ItemMediaBulkController::class, 'bulkUpload']);
```

#### 考慮事項

- ZIPファイルの展開はサーバーメモリを消費するため、大きなファイルはキューで処理することも検討
- 既に画像が登録されている生体に対してZIPアップロードした場合は、既存画像に追加する（上書きしない）
- ファイル名が命名規則に合わない場合はスキップしてエラーレポートに含める
- ネストされたフォルダ構造のZIPにも対応（フォルダ名は無視し、ファイル名のみで判定）
