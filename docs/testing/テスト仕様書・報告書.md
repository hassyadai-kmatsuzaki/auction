## 1. テスト概要

### 1.1 目的

本テスト計画は、日本メダカオンライン市場の品質を保証するため、以下の観点からテストを実施します。

| テスト種別 | 主な目的 | ツール |
|---|---|---|
| 単体テスト | クラス・メソッド単位の動作保証 | PHPUnit 11 / Vitest |
| 統合テスト | DB・API・外部サービス連携の動作保証 | PHPUnit + SQLite/MySQL |
| E2Eテスト | ユーザーシナリオ全体の動作保証 | Cypress 15 |
| 負荷テスト | 同時接続500人対応の性能保証 | k6 |
| セキュリティテスト | OWASP Top 10・脆弱性の排除 | 手動 + 自動ツール |

### 1.2 テスト対象バージョン

- バックエンド: Laravel 12 (PHP 8.2+)
- フロントエンド: React 18.3 + TypeScript 5.6
- データベース: MySQL 8.0

### 1.3 カバレッジ目標

| 対象 | 目標カバレッジ |
|---|---|
| PHP バックエンド（行カバレッジ） | **80%以上** |
| フロントエンド（ブランチカバレッジ） | 70%以上 |
| 主要ビジネスロジック（入札・決済） | **90%以上** |

## 2. テスト環境

### 2.1 バックエンドテスト環境

```
OS: Amazon Linux 2023 (CI: Ubuntu 22.04)
PHP: 8.2+
データベース: SQLite (単体) / MySQL 8.0 (統合)
Redis: Valkey 8.0 (モック または 実サービス)
テストフレームワーク: PHPUnit 11.5
```

```bash
# テスト実行コマンド
cd /var/www/auction

# 全テスト実行
php artisan test

# カバレッジ付き実行
php artisan test --coverage --min=80

# 特定テストクラス実行
php artisan test tests/Unit/Actions/JoinBidActionTest.php

# 並列実行
php artisan test --parallel
```

### 2.2 フロントエンドテスト環境

```
Node.js: 20+
テストフレームワーク: Vitest 4
E2Eフレームワーク: Cypress 15
```

```bash
# Vitest 実行
npm run test

# カバレッジ付き
npm run test -- --coverage

# Cypress E2E（ヘッドレス）
npx cypress run

# Cypress E2E（GUI モード）
npx cypress open
```

下図が本章の総合E2E。これを単一のシナリオスイート `e2e/post-auction-golden.cy.ts` として実装する。

```
[1] オークション終了 → WonItem 自動生成
      ↓ 非同期で NTF-1（落札者）/ NTF-2（出品者）
[2] 落札者: 配送先住所を登録（未ロック時のみ）
      ↓
[3] 落札者: 配送料計算 POST → shipping_calculated_at 更新
      ↓
[4] 落札者: 請求書 PDF ダウンロード（/participant/…/invoice）
      ↓
[5] 落札者: 入金実施（本テストでは管理者が paid に遷移させて模倣）
      ↓ 24h/1h の催促ジョブで NTF-6/7（期限設定に応じて）
[6] 管理者: 入金確認（A-4）→ confirmed / shipping_locked_at 設定
      ↓ NTF-3（落札者）/ NTF-4（出品者）
[7] 落札者: 領収書 PDF ダウンロード（/participant/…/receipt）
[8] 出品者 or 管理者: 発送登録（S-3 or A-5）
      ↓ NTF-5（落札者）
[9] 管理者: 配達完了（A-6）→ delivery_status=completed
[10] 出品者: 支払通知書 PDF ダウンロード（S-7）
[11] 管理者: 精算ステータス更新 → 振込完了（A-18）
[12] 帳票一覧（A-12/13/14）で INV/PAY/DLV が全て生成済みに表示
```

**合否**: 全ステップ HTTP 2xx・DB 状態が §10.1 の遷移に一致・通知がキューに積まれることを `Queue::fake()` 相当（staging 実体は MailHog + LINE テストBot）で検証。

| PERF-01 | `/admin/auctions/{id}/won-items` 1000件 | p95 < 1.5s |
| PERF-02 | PDF 生成 1 件 | p95 < 3s |
| PERF-03 | 催促ジョブ 10,000 WonItem スキャン | 実行時間 < 60s（30分おきスケジュールの1/30） |
| PERF-04 | 帳票一覧 CSV 出力 10,000 行 | p95 < 10s / メモリ < 256MB |
| SEC-01 | PDF に他落札者情報が混入しない | PDF テキスト内に自分以外の氏名なし |

| SEC-04 | LINE 本文に銀行口座番号など機微情報を載せない | 含まれないこと |

### 10.16 実行手順と合格基準

```bash
# ステージング DB リセット
ssh staging "cd /var/www/auction && php artisan migrate:fresh --seed --env=staging"

# Queue Worker と Scheduler を明示起動（supervisor 経由）

# Cypress 実行
cd src && npx cypress run --spec 'cypress/e2e/post-auction-*.cy.ts' \
  --env E2E_ADMIN_EMAIL=...,E2E_SELLER_EMAIL=...,E2E_PARTICIPANT_EMAIL=...

# 催促ジョブは手動発火
ssh staging "cd /var/www/auction && php artisan schedule:run"
```
