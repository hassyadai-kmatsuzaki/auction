# 落札後フロー機能 ビジネスサイド向け説明書

## はじめに

本ドキュメントは、メダカオークションの「落札後フロー」機能について、ビジネスサイドの関係者向けに**できること・できないこと**を網羅的にまとめたものです。

---

## 1. 機能全体像

オークション終了後、以下の一連の処理が**全自動**で実行されます。

```
オークション終了
  ↓
落札者に請求書を自動送付（PDF + メール + LINE）
  ↓
入金を自動確認（銀行データと照合）
  ↓
未入金者には自動でリマインド送信
  ↓
出品者に振込実行後、支払通知書を自動送付（PDF + メール + LINE）
```

## 3. できないこと・制約事項

### 3.1 入金関連の制約

| # | できないこと | 理由・補足 |
|---|------------|-----------|
| 1 | **銀行口座への自動振込** | 銀行APIとの直接連携は対象外です。振込の実行自体は管理者が銀行サイトや窓口で行う必要があります。システムは「振込完了の記録」とその後の自動通知を担います |
| 2 | **リアルタイムの入金検知** | 銀行データはCSVファイルのアップロードによる取り込みです。リアルタイムで口座の入金を検知することはできません。取り込みの頻度は運用で決める形になります |
| 3 | **銀行フォーマットの自動認識** | 銀行ごとにCSVフォーマットが異なるため、初期対応は主要銀行1行分のみです。他行は順次対応が必要です |
| 4 | **部分入金の自動処理** | 請求金額と異なる金額が振り込まれた場合、自動照合はできません。管理者が手動で対応する必要があります |
| 5 | **返金処理の自動化** | 返金が必要な場合（キャンセル・金額間違い等）は、管理者が手動で対応する必要があります |

### 3.2 請求書・支払通知書の制約

| # | できないこと | 理由・補足 |
|---|------------|-----------|
| 6 | **発行済み請求書の金額修正** | 一度発行した請求書の金額を直接編集することはできません。変更が必要な場合は「再発行」（旧請求書取消→新請求書発行）で対応します |
| 7 | **請求書の分割発行** | 1つのオークション内で同一落札者が落札した商品は、1通の請求書にまとめられます。「商品Aだけ先に請求」のような分割発行はできません |
| 8 | **請求書の手動作成** | 請求書はオークション終了時に自動生成されます。任意のタイミングで手動で請求書を新規作成することはできません |
| 9 | **支払通知書の事前発行** | 支払通知書は振込完了後に自動生成されます。振込前に事前発行することはできません |
| 10 | **PDFデザインの自由カスタマイズ** | PDFのレイアウトはシステムで定義されたテンプレートに基づきます。ユーザーが自由にデザインを変更することはできません（テンプレート変更には開発対応が必要です） |

### 3.3 手数料・送料の制約

| # | できないこと | 理由・補足 |
|---|------------|-----------|
| 11 | **アイテム単位の手数料設定** | 手数料率の設定はシステム全体/オークション単位/出品者単位です。「この商品だけ手数料3%」のようなアイテム単位の設定はできません |
| 12 | **過去の請求書への設定遡及適用** | 手数料率を変更しても、既に発行された請求書には反映されません（これは意図した仕様です） |
| 13 | **送料の完全自動計算（実重量ベース）** | 送料は「地域×箱サイズ」のマトリクスで計算します。実際の重量に基づく送料計算はできません |
| 14 | **複数配送先への分割配送** | 1つの請求書に対する配送先は1箇所です。同一落札者が複数の配送先を指定することはできません |

### 3.4 通知の制約

| # | できないこと | 理由・補足 |
|---|------------|-----------|
| 15 | **通知テンプレートの自由編集** | メール・LINEの文面はシステムで定義されています。管理画面から文面を自由に編集することはできません（変更には開発対応が必要です） |
| 16 | **SMS通知** | 通知チャネルはメール・LINE・Slackの3種です。SMSへの通知は対応していません |
| 17 | **通知の時間帯指定** | 請求書や入金確認の通知はイベント発生時に即時送信されます。「朝9時にまとめて送信」のような時間帯指定はできません（未入金リマインドのみ朝9時固定） |
| 18 | **LINE未連携ユーザーへのLINE通知** | LINEアカウントを連携していないユーザーにはLINE通知が届きません。メール通知のみとなります |

### 3.5 その他の制約

| # | できないこと | 理由・補足 |
|---|------------|-----------|
| 19 | **多通貨対応** | 全ての金額計算は日本円のみです。外貨での取引には対応していません |
| 20 | **クレジットカード決済** | 支払い方法は銀行振込のみです。クレジットカード・電子マネー等のオンライン決済には対応していません |
| 21 | **出品者からの直接請求** | 出品者が落札者に直接請求書を発行する機能はありません。全て運営を経由します |
| 22 | **会計ソフト連携** | freee・弥生・マネーフォワード等の会計ソフトとの直接連携はありません。データはCSVエクスポートで対応します |
| 23 | **電子帳簿保存法の完全対応** | 電子帳簿保存法への準拠は本スコープ外です。PDFの保存・タイムスタンプ等の要件は別途検討が必要です |
| 24 | **落札後のキャンセルフロー** | 落札後のキャンセル（落札者都合・出品者都合）に伴う請求書取消・返金フローは本スコープ外です |

## 4. 運用上の前提条件

本機能を正常に運用するために、以下が前提となります。

| # | 前提条件 | 説明 |
|---|---------|------|
| 1 | 銀行CSVの定期取り込み | 入金の自動消し込みには、銀行CSVを管理画面からアップロードする運用が必要です |
| 2 | 振込作業は手動 | 出品者への振込は管理者が銀行サイト/窓口で手動実行し、その後システムに完了を記録します |
| 3 | Slack連携の事前設定 | Slack通知には、Incoming Webhook の設定と #auction-payments チャンネルの作成が必要です |
| 4 | LINE連携の事前設定 | LINE通知には、LINE Messaging APIの設定と各ユーザーのLINE連携が必要です |
| 5 | メール送信環境 | SMTPサーバーまたはメール送信サービス（SES等）の設定が必要です |
| 6 | インボイス番号の事前登録 | インボイス制度対応には、出品者・落札者のインボイス登録番号を事前に登録する必要があります |
| 7 | 配送情報の事前登録 | 送料自動計算には、落札者の配送先地域・希望箱サイズの登録が必要です |

## 5. 金額計算の仕組み（概要）

### 5.1 落札者が支払う金額

```
落札者の支払総額 = 落札金額合計 + 手数料 - 割引（※） + 送料

  手数料 = 落札金額合計 × 手数料率（デフォルト5%）
          ※最低¥300（手数料率計算が¥300未満の場合）

  割引   = インボイス登録事業者の場合のみ適用

  送料   = 配送の場合: 基本送料 + 梱包料 + 取扱手数料 + 保険料 + 季節料金
           引き取りの場合: ¥0
```

### 5.2 出品者が受け取る金額

```
出品者の受取額 = 落札金額合計 - 出品手数料 + 割引（※） - 送料 - プレミアム出品費

  出品手数料 = 落札金額合計 × 手数料率（デフォルト10%）
              ※最低¥500（手数料率計算が¥500未満の場合）

  割引       = インボイス登録事業者の場合のみ適用

  プレミアム出品費 = プレミアム出品アイテム数 × ¥300/件
                    ※プレミアム出品がない場合は¥0
```

### 5.3 計算例

#### 落札者の例（落札金額¥10,000、配送/関東/60サイズ/7月）

| 項目 | 金額 |
|------|------|
| 落札金額合計 | ¥10,000 |
| 手数料（5%） | ¥500 |
| 送料（基本¥800 + 梱包¥500 + 取扱¥300 + 保険¥300 + クール便¥300） | ¥2,200 |
| **支払総額** | **¥12,700** |

#### 出品者の例（落札金額¥10,000、プレミアム出品1件）

| 項目 | 金額 |
|------|------|
| 落札金額合計 | ¥10,000 |
| 出品手数料（10%） | -¥1,000 |
| プレミアム出品費（1件） | -¥300 |
| **受取額** | **¥8,700** |

## 6. 設定変更と過去書類の関係

### 6.1 ポイント

**設定はいつでも変えられますが、過去に発行した書類の金額には影響しません。**

これは「発行時スナップショット」という仕組みによるものです。請求書や支払通知書を発行する瞬間に、その時点の手数料率・送料テーブル・各種料金を全てコピーして書類内に保存します。

### 6.2 具体例

```
3月のオークション: 手数料5% → 請求書は5%で発行
  ↓
4月に手数料を8%に変更
  ↓
4月のオークション: 請求書は8%で発行
  ↓
3月の請求書を管理画面で確認 → 5%のまま表示される（変わらない）
```

### 6.3 再発行した場合

管理者が請求書を「再発行」した場合は、**再発行時点の最新設定**が適用されます。元の請求書は取り消し扱いで記録が残ります。

## 8. よくある質問（FAQ）

### Q1. 手数料率を途中で変更したら、すでに終わったオークションの請求書はどうなりますか？

**A.** 変わりません。請求書は発行時の手数料率で金額が確定しており、後から設定を変更しても影響を受けません。

### Q2. 落札者が振込額を間違えた場合はどうなりますか？

**A.** 自動照合では金額が一致しないため、不一致として処理されます。管理者が管理画面から手動で紐付けるか、落札者に連絡して対応してください。

### Q3. 出品者への振込は自動ですか？

**A.** いいえ。振込の実行自体は管理者が手動で行います。システムは「振込完了の記録」とその後の支払通知書送付を自動化します。

### Q4. 落札者がLINEを連携していない場合、通知は届きますか？

**A.** LINE通知は届きませんが、メール通知は届きます。重要な通知は必ずメールでも送信されます。

### Q5. 一度発行した請求書の金額を修正できますか？

**A.** 直接修正はできません。「再発行」機能で、元の請求書を取り消して新しい請求書を発行する形になります。

### Q6. オークション単位で手数料率を変えることはできますか？

**A.** はい。オークション作成時に個別の手数料率を設定できます。設定しない場合はシステムデフォルトの手数料率が適用されます。

### Q7. 請求書のPDFデザインを変更できますか？

**A.** 管理画面からの変更はできません。デザイン変更には開発対応が必要です。ただし、記載する情報（会社名・銀行口座等）はシステム設定から変更可能です。

### Q8. 将来的にクレジットカード決済やコンビニ払いに対応できますか？

**A.** 現在のスコープには含まれていませんが、アーキテクチャ上は決済手段を追加できる設計です。対応する場合は別途開発が必要です。
