## 1. 概要

オークション×出品者単位で 1 件の精算レコード (`SellerSettlement`) が作成され、落札商品の集計・手数料計算・出品者への支払い記録までを管理します。

### 1.1 用語

| 用語 | 定義 |
|---|---|
| SellerSettlement | オークション × 出品者単位の精算レコード |
| sales_total | 売上合計（落札金額の総和） |
| commission | 手数料（売上 × commission_rate） |
| net_amount | 出品者受取額 = sales_total − commission |
| WonItem | 落札明細。精算の集計元 |

## 2. データモデル

### 2.1 seller_settlements テーブル

| カラム | 型 | 説明 |
|---|---|---|
| `id` | PK | 主キー |
| `auction_id` | FK → auctions | オークション |
| `seller_profile_id` | FK → seller_profiles | 出品者 |
| `status` | enum | `pending` / `processing` / `completed` / `on_hold` / `cancelled` |
| `total_sales` | DECIMAL(12,2) | 売上合計 |
| `total_commission` | DECIMAL(12,2) | 手数料合計 |
| `total_shipping_fee` | DECIMAL(12,2) | 送料合計（手数料対象外） |
| `net_amount` | DECIMAL(12,2) | 出品者受取額 |
| `items_count` | UNSIGNED INT | 落札件数 |
| `scheduled_payment_date` | TIMESTAMP, nullable | 振込予定日 |
| `paid_at` | TIMESTAMP, nullable | 振込実施日時 |
| `paid_by` | FK → users, nullable | 振込処理を行った管理者 |
| `payment_method` | VARCHAR(50), nullable | 振込 / 現金 / その他 |
| `transaction_reference` | VARCHAR(120), nullable | 振込番号・参照番号 |
| `note` | TEXT, nullable | 補足 |
| `created_at` / `updated_at` | timestamps | |

> 集計値（`total_sales` 等）はパフォーマンスのため冗長保持し、参照時に `recalculateTotals()` で更新する設計。

### 2.2 WonItem 側の対応カラム

精算の集計元となる WonItem のカラム:

| カラム | 説明 |
|---|---|
| `total_amount` | 落札合計（落札価格 + 送料） |
| `commission_rate` | 手数料率（DECIMAL(5,2)、デフォルト 10%） |
| `commission_amount` | 手数料額 |
| `seller_amount` | 出品者受取額 = total_amount − commission_amount |
| `shipping_fee` | 送料 |

## 3. 状態遷移

```
pending ──update──▶ processing ──update / mark-paid──▶ completed
   │                                                    ▲
   ├──update──▶ on_hold ─────────update──────────────┘
   │
   └──update──▶ cancelled  （任意の状態から遷移可、再計算不可）
```

### 3.1 遷移ルール ([Admin/SettlementController.php](../../../app/Http/Controllers/Admin/SettlementController.php))

| 遷移先 | 自動付与 | 自動クリア |
|---|---|---|
| `completed` | `paid_at = now()`, `paid_by = 管理者ID`（未指定時のみ） | — |
| `completed` 以外 | — | `paid_at`, `paid_by` をクリア（誤操作の巻き戻し対応） |
| `cancelled` | — | 以降の `recalculate` 不可 |

## 4. 計算ロジック

### 4.1 再計算メソッド

`SellerSettlement::recalculateTotals()` ([app/Models/SellerSettlement.php](../../../app/Models/SellerSettlement.php)):

```sql
SELECT
  SUM(won_items.total_amount)       AS total_sales,
  SUM(won_items.commission_amount)  AS total_commission,
  SUM(won_items.seller_amount)      AS net_amount,
  SUM(won_items.shipping_fee)       AS total_shipping_fee,
  COUNT(*)                          AS items_count
FROM won_items
  JOIN items ON won_items.item_id = items.id
WHERE items.auction_id = ?
  AND items.seller_profile_id = ?
```

### 4.2 計算タイミング

| トリガー | 説明 |
|---|---|
| 管理者が詳細表示 | `Admin/SettlementController::show()` で `recalculateTotals()` を自動呼び出し |
| レコード自動生成時 | `syncMissingSettlements()` で新規作成直後に計算 |
| 手動再計算 | `POST /admin/settlements/{id}/recalculate` |

### 4.3 手数料率の決定

- 各 WonItem に `commission_rate` を保持（落札確定時にスナップショット）
- デフォルトは 10%（システム設定で変更可）
- 集計時は WonItem の `commission_amount` を合算するだけ

### 4.4 税区分

- **外税方式**: `InvoiceService` での PDF 生成時に `tax_rate = 10%` を別途加算
- 落札価格・手数料はすべて税抜き表示
- 送料は手数料対象外

## 5. API エンドポイント

### 5.1 管理者向け

ルートプレフィックス: `/api/admin/settlements`

| メソッド | パス | 責務 |
|---|---|---|
| GET | `/` | 一覧（WonItem から自動補完） |
| GET | `/{id}` | 詳細（show 時に再計算） |
| PATCH | `/{id}` | status・支払情報更新 |
| POST | `/{id}/mark-paid` | status を `completed` に簡易遷移 |
| POST | `/{id}/recalculate` | WonItem から強制再集計 |

### 5.2 出品者向け

ルートプレフィックス: `/api/seller/settlements`

| メソッド | パス | 責務 |
|---|---|---|
| GET | `/` | 売上サマリ（オークション単位） |
| GET | `/{auctionId}` | オークション単位の精算詳細 |
| GET | `/{auctionId}/payment-notice` | 支払通知書 PDF（[InvoiceController](../../../app/Http/Controllers/Api/InvoiceController.php)） |

#### 出品者ダッシュボードの追加情報

`/api/seller/settlements` のレスポンスには以下も含まれる:

- 月別売上データ（過去 6 ヶ月）
- 銀行口座情報（seller_profile から）
- 次回精算予定（最も近い `scheduled_payment_date`）

## 6. 自動生成タイミング

`SellerSettlement` は **Lazy 生成** ― 初回参照時に作成されます。バッチジョブによる事前生成は行いません。

| 実装場所 | トリガー | 動作 |
|---|---|---|
| `Admin/SettlementController::index` | 管理者が一覧アクセス | 存在しない `(auction, seller)` の組を WonItem から検出して `pending` で作成 |
| `Seller/SettlementController::index` | 出品者が一覧アクセス | `firstOrCreate` で未作成時に `pending` で作成 |
| `Seller/SettlementController::show` | 出品者が詳細アクセス | 同上 |

## 7. 支払通知書 PDF

### 7.1 生成元

`InvoiceService::generateSellerPaymentNotice()` ([app/Services/InvoiceService.php](../../../app/Services/InvoiceService.php))

### 7.2 出力内容

| 項目 | 内容 |
|---|---|
| 文書番号 | `PAY-YYYYMMDD-A{auctionId:05d}-S{sellerId:05d}` |
| 出品者名 | seller_profile.display_name |
| オークション | 名称・開催日 |
| 明細行 | item_number / species_name / buyer_name / quantity / total_amount / commission_amount / seller_amount |
| 集計 | total_sales / total_commission / net_amount |
| 振込予定日 | オークション終了日 + 7 日 |
| 振込先 | seller_profile の bank_name / bank_branch / account_type / account_number / account_holder |

### 7.3 ダウンロード経路

- 出品者: `GET /api/seller/settlements/{auctionId}/payment-notice`
- 管理者: `GET /api/admin/auctions/{auctionId}/sellers/{sellerId}/payment-notice`

## 8. 運用フロー

### 8.1 標準フロー

```
[1] オークション終了 → WonItem 自動生成
[2] 管理者または出品者が精算画面を開く → SellerSettlement 自動生成（status=pending）
[3] 管理者が落札者ごとの入金確認を行う（WonItem 単位）
[4] 全件入金確認後、管理者が精算 status を processing に更新
[5] 銀行で振込実施 → 管理者が mark-paid または PATCH で completed に
    └ paid_at / paid_by が自動セット
[6] 出品者が支払通知書 PDF をダウンロード
```

### 8.2 イレギュラー

| ケース | 対応 |
|---|---|
| 落札後に商品追加・削除 | `recalculate` で集計を更新 |
| 振込先口座未登録 | `on_hold` に遷移し、出品者へ口座登録を促す |
| 紛争・返金が発生 | `cancelled` に遷移（`recalculate` 不可） |
| 振込ミスで巻き戻し | status を `processing` に戻すと `paid_at` / `paid_by` が自動クリア |

## 10. 運用上の注意点

1. **Lazy 生成のリスク**: アクセスがないと `SellerSettlement` レコードは作られない。月次レポート生成バッチでは `syncMissingSettlements()` を明示的に呼ぶこと
2. **commission_rate のスナップショット**: 落札確定時に WonItem に保存されるため、後からシステム設定を変えても過去分には影響しない（仕様）
3. **送料の扱い**: `total_shipping_fee` は集計には含めるが手数料計算からは除外
4. **巻き戻しの副作用**: status を `completed` から戻すと `paid_at` / `paid_by` がクリアされる。意図せぬ巻き戻しは経理処理に影響するので慎重に
5. **PDF 番号の一意性**: `PAY-YYYYMMDD-A...` の日付部分は生成日。再発行時は同じ精算でも番号が変わる点に注意
