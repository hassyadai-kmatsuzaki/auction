## ドキュメント整理の方針

- **本ディレクトリ (`src/docs/`) を唯一の正本** とします。リポジトリルートの `docs/` は使いません
- 機能別仕様は `features/<機能名>/` 配下に 1 ファイルずつ配置
- 横断的なリファレンス（API・DB 設計）は `api/` `architecture/` に配置
- ドキュメント間のリンクは相対パスで記述（リポジトリ内ナビゲーション可能）
- 実装ファイルへのリンクは `../../app/...` のような src ルート相対で記述
- 各機能仕様書の末尾には「関連ドキュメント」セクションを設置

| ドキュメント | 更新タイミング |
|---|---|
| 要件定義 / DB 設計 / API リファレンス | スキーマ・要件変更時 |
| 機能別仕様 | 該当機能の実装変更時 |
| インフラ系 | インフラ変更・AWS リソース追加時 |
| 運用系 | 運用フロー変更時・インシデント発生時の振り返り |
| テスト | 新機能のテスト追加時・テスト結果の反映時 |
| ユーザーマニュアル | UI 変更時 |
