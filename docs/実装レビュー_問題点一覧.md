## 🔴 クリティカル（即時対応必要）

### 1. パスワード設定後もログインできない問題

**ファイル**: `SetPasswordController.php`

**問題**: ユーザー作成時に `status = 'pending'` で作成されるが、パスワード設定後も `status` が `pending` のまま。`LoginController` では `status === 'approved'` でないとログインを拒否するため、新規ユーザーがログインできない。

**現状のコード**:
```php
// SetPasswordController.php line 80-83
$user->update([
    'password' => Hash::make($request->password),
    'email_verified_at' => now(),
]);
// status が 'pending' のまま
```

**修正案**:
```php
$user->update([
    'password' => Hash::make($request->password),
    'email_verified_at' => now(),
    'status' => 'approved',  // 追加
]);
```

### 2. オークションの「予定」ステータスへの遷移ができない

**ファイル**: `AuctionController.php`

**問題**: `updateStatus` メソッドで `'scheduled'` が許可されていないため、`preparing` → `scheduled` への遷移ができない。

**現状のコード**:
```php
// AuctionController.php line 260-262
$validator = Validator::make($request->all(), [
    'status' => 'required|in:live,finished,cancelled',  // 'scheduled' がない
]);
```

**修正案**:
```php
$validator = Validator::make($request->all(), [
    'status' => 'required|in:scheduled,live,finished,cancelled',
]);

// switch文にも追加
case 'scheduled':
    if (!in_array($auction->status, ['preparing'])) {
        return response()->json([
            'success' => false,
            'message' => '準備中のオークションのみ予定にできます。',
        ], 400);
    }
    $auction->update(['status' => 'scheduled']);
    $message = 'オークションを予定に設定しました。';
    break;
```

### 3. フロントエンドの型定義がバックエンドと不一致

**ファイル**: `src/resources/ts/types/index.ts`

**問題1**: `Auction` 型に `scheduled` ステータスがない
```typescript
// 現状
status: 'preparing' | 'live' | 'finished' | 'cancelled';

// 修正
status: 'preparing' | 'scheduled' | 'live' | 'finished' | 'cancelled';
```

**問題2**: `Announcement` 型がバックエンドと完全に異なる
```typescript
// 現状（古い型定義）
export interface Announcement {
  id: number;
  title: string;
  content: string;
  is_published: boolean;        // ← 存在しない
  published_at?: string;
  expires_at?: string;          // ← 存在しない
  priority: 'low' | 'normal' | 'high';  // ← 存在しない
  created_by: number;
  is_read?: boolean;
  created_at: string;
}

// 修正（バックエンドと一致させる）
export interface Announcement {
  id: number;
  title: string;
  content: string;
  status: 'draft' | 'scheduled' | 'published' | 'hidden';
  target_roles: string[];
  is_important: boolean;
  published_at: string | null;
  created_by: number;
  updated_by: number | null;
  created_at: string;
  updated_at: string;
}
```

**問題3**: `User` 型に `roles` が定義されていない
```typescript
// 修正
export interface User {
  id: number;
  name: string;
  email: string;
  status: 'pending' | 'approved' | 'suspended' | 'rejected';
  phone?: string;
  postal_code?: string;
  prefecture?: string;
  city?: string;
  address_line1?: string;
  address_line2?: string;
  roles: Role[];
  created_at: string;
}

export interface Role {
  id: number;
  name: string;
  display_name: string;
}
```

## 🟠 高優先度

### 4. Auctionモデルの start_time キャストが不正

**ファイル**: `Auction.php`

**問題**: `datetime:H:i` はキャストとして機能しない。

**現状**:
```php
protected $casts = [
    'start_time' => 'datetime:H:i',  // ← 不正
    'end_time' => 'datetime:H:i',    // ← 不正
];
```

**修正案**:
```php
protected $casts = [
    'start_time' => 'datetime',
    'end_time' => 'datetime',
];
```

---

### 5. Announcement Model の `isVisibleToUser` メソッドの null チェック不足

**ファイル**: `Announcement.php`

**問題**: `published_at` が `null` の場合、`$this->published_at > now()` がエラーになる可能性。

**現状**:
```php
if ($this->published_at > now()) {
    return false;
}
```

**修正案**:
```php
if ($this->published_at && $this->published_at > now()) {
    return false;
}
```

---

### 6. お知らせの「非表示→公開」時に `published_at` が設定されない

**ファイル**: `Admin/AnnouncementController.php`

**問題**: `toggleVisibility` で `hidden` → `published` に変更する際、`published_at` が null のままだと、ユーザーに表示されない（`visibleTo` スコープで `published_at <= now()` を条件にしているため）。

**修正案**:
```php
elseif ($announcement->status === 'hidden') {
    $updateData = [
        'status' => 'published',
        'updated_by' => Auth::id(),
    ];
    
    // published_at が未設定の場合は現在時刻を設定
    if (!$announcement->published_at) {
        $updateData['published_at'] = now();
    }
    
    $announcement->update($updateData);
    $message = 'お知らせを公開しました。';
}
```

## 🟡 中優先度

### 8. N+1問題の可能性

**ファイル**: `Auction.php`

**問題**: `canDelete()` で `$this->items()->count()` を呼んでいるが、一覧取得時に各レコードごとにクエリが発行される可能性。

**修正案**: コントローラーで `withCount('items')` を使用し、`items_count` で判定する。

### 9. エラーハンドリングの統一不足

**ファイル**: 各フロントエンドコンポーネント

**問題**: エラー時に `alert()` を使用しており、UXが悪い。

**修正案**: MUIの `Snackbar` または `Alert` コンポーネントを使用したグローバルな通知システムを実装。

### 10. トランザクション内でのメール送信

**ファイル**: `Admin/UserController.php`

**問題**: `store` メソッドでトランザクション内でメール送信を行っている。メール送信が遅延すると、長時間ロックが発生する可能性。

**修正案**: メール送信をキューに移行するか、トランザクション外で実行。

```php
DB::commit();

// トランザクション外でメール送信
Mail::to($user->email)->queue(new SetPasswordMail($user, $verificationUrl));
```
