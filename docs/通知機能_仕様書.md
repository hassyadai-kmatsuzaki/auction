# 通知機能 仕様書

## 1. 概要

本システムでは **LINE通知** と **メール通知** の2チャネルで、オークションに関するイベント通知をユーザーに配信する。
通知はユーザーのロール（参加者 / 出品者）および通知設定に基づいて送信される。

---

## 2. 通知チャネル

| チャネル | 技術 | 設定 |
|----------|------|------|
| メール | Laravel Mail（`Mail::queue` による非同期送信） | SMTP / SES 等（`config/mail.php`） |
| LINE | LINE Messaging API（Push Message） | `config/services.php` → `services.line` |

### 環境変数

```env
# メール
MAIL_MAILER=smtp
MAIL_HOST=
MAIL_PORT=2525
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM_ADDRESS=
MAIL_FROM_NAME=

# LINE
LINE_LOGIN_CHANNEL_ID=
LINE_LOGIN_CHANNEL_SECRET=
LINE_LOGIN_REDIRECT_URI=
LINE_MESSAGING_CHANNEL_ACCESS_TOKEN=
```

## 4. 通知フロー

```
イベント発生
    ↓
NotificationService.send*Notification()
    ├─ 通知設定チェック（User.notification_settings / SellerProfile.notification_settings）
    ├─ メール送信: Mail::queue(new *Mail(...))  [非同期]
    └─ LINE送信: LineService::notify()
        ├─ LineAccount.is_active チェック
        ├─ LineNotificationSetting チェック
        ├─ LINE Messaging API Push Message
        └─ LineNotificationLog に記録（status: sent/failed/skipped）
```

## 5. LINE連携

### 5.1 アカウント連携フロー

```
1. ユーザーが設定画面で「LINEと連携」をタップ
2. GET /api/settings/line/redirect → LINE Login OAuth URL を返却
3. LINE認証 → コールバック GET /api/auth/line/callback
4. LinkLineAccountAction: アクセストークン取得 → プロフィール取得 → LineAccount 作成/更新
5. フロントエンドにリダイレクト（success/error）
```

### 5.2 LINE通知設定API

| メソッド | エンドポイント | 説明 |
|----------|--------------|------|
| GET | `/api/settings/line/redirect` | LINE OAuth URL を取得 |
| GET | `/api/auth/line/callback` | OAuth コールバック |
| GET | `/api/settings/line/status` | 連携ステータス確認 |
| DELETE | `/api/settings/line/unlink` | 連携解除（`is_active=false`） |
| GET | `/api/settings/line/notifications` | 通知設定一覧取得 |
| PUT | `/api/settings/line/notifications` | 通知設定更新 |

### 5.3 LINE通知種別

| notification_type | 説明 | デフォルト |
|-------------------|------|-----------|
| `auction_start` | オークション開始通知 | 有効 |
| `won_item` | 落札通知 | 有効 |
| `payment_reminder` | 入金催促 | 有効 |
| `shipping_completed` | 発送完了通知 | 有効 |
| `auction_preview` | オークション予告（前日） | 有効 |
| `bid_limit_reached` | 指値発動通知 | 有効 |
| `new_auction` | 新規オークション通知 | 有効 |
| `favorite_approaching` | お気に入り順番接近通知 | 有効 |

> **注:** 設定レコードが存在しない場合はデフォルト「有効」として扱う

## 10. スケジュールジョブ

| ジョブ | スケジュール | 説明 |

> 登録場所: `bootstrap/app.php` の `withSchedule()` / `withoutOverlapping()` で多重実行防止

## 11. 既知の問題・対応状況

### 対応済み

| # | 問題 | 対応内容 |
|---|------|---------|
| 1 | `auction_preview`（前日予告）が未実装 | `SendAuctionPreviewJob` + `AuctionPreviewMail` を実装 |
| 2 | `payment_reminder`（入金催促）のトリガーなし | `SendPaymentReminderJob` を実装（30分毎） |
| 3 | LINE通知が同期送信でブロック | `SendLineNotificationJob::dispatch()` による非同期化 |
| 4 | `BidLimitReached` メールに設定チェックなし | `shouldSendParticipantNotification('email_bid_limit_reached')` を追加 |
| 5 | `FavoriteApproaching` が直接送信 | `NotificationService::sendFavoriteApproachingNotification()` に統合 |

### LOW — 将来対応

| # | 問題 | 対応方針 |
|---|------|---------|
| 6 | LINE無料プラン月200通のレート制限チェックなし | `LineNotificationLog` のカウントでチェック、超過時はメールにフォールバック |
| 7 | 出品者向けLINE通知設定が参加者と同じ `notification_type` リストを共有 | ロール別の通知タイプリストを分離 |
| 8 | メールバウンス・配信停止のトラッキングなし | SES等のWebhookで配信状態を管理 |
