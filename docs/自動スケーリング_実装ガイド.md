##### AuctionObserver（スケジュール自動登録）

```php
// app/Observers/AuctionObserver.php

class AuctionObserver
{
    public function __construct(
        private ScheduleInfraScalingAction $scheduleAction
    ) {}

    public function created(Auction $auction): void
    {
        $this->scheduleAction->execute($auction);
    }

    public function updated(Auction $auction): void
    {
        // event_date が変更された場合のみ再スケジュール
        if ($auction->isDirty('event_date')) {
            $this->scheduleAction->execute($auction);
        }
    }

    public function deleted(Auction $auction): void
    {
        $this->scheduleAction->cancel($auction);
    }
}
```

##### ScheduleInfraScalingAction（EventBridge Schedule 作成）

```php
// app/Actions/Infra/ScheduleInfraScalingAction.php

namespace App\Actions\Infra;

use App\Models\Auction;
use Aws\Exception\AwsException;
use Aws\Scheduler\SchedulerClient;
use Carbon\Carbon;
use Illuminate\Support\Facades\Log;

class ScheduleInfraScalingAction
{
    private SchedulerClient $scheduler;

    public function __construct()
    {
        $this->scheduler = new SchedulerClient([
            'region'  => config('services.aws.region', 'ap-northeast-1'),
            'version' => 'latest',
        ]);
    }

    public function execute(Auction $auction): void
    {
        $eventDate = $auction->event_date; // Carbon instance

        // 既存スケジュールがあれば削除（日程変更対応）
        $this->cancel($auction);

        // スケールアップ: 開催2日前の AM 3:00 (JST)
        $scaleUpAt = $eventDate->copy()->subDays(2)->setTime(3, 0, 0);
        if ($scaleUpAt->isFuture()) {
            $this->createSchedule(
                name: "auction-{$auction->id}-scale-up",
                at: $scaleUpAt,
                input: ['action' => 'scale-up', 'auction_id' => $auction->id],
            );
        }

        // スケールダウン: 開催2日後の AM 3:00 (JST)
        $scaleDownAt = $eventDate->copy()->addDays(2)->setTime(3, 0, 0);
        $this->createSchedule(
            name: "auction-{$auction->id}-scale-down",
            at: $scaleDownAt,
            input: ['action' => 'scale-down', 'auction_id' => $auction->id],
        );

        Log::info("Infra scaling scheduled for auction {$auction->id}", [
            'scale_up_at'   => $scaleUpAt->toIso8601String(),
            'scale_down_at' => $scaleDownAt->toIso8601String(),
        ]);
    }

    public function cancel(Auction $auction): void
    {
        foreach (['scale-up', 'scale-down'] as $action) {
            try {
                $this->scheduler->deleteSchedule([
                    'Name' => "auction-{$auction->id}-{$action}",
                ]);
            } catch (\Aws\Exception\AwsException $e) {
                // NotFound は無視（初回作成時）
                if ($e->getAwsErrorCode() !== 'ResourceNotFoundException') {
                    throw $e;
                }
            }
        }
    }

    private function createSchedule(string $name, Carbon $at, array $input): void
    {
        $this->scheduler->createSchedule([
            'Name' => $name,
            'ScheduleExpression' => "at({$at->format('Y-m-d\TH:i:s')})",
            'ScheduleExpressionTimezone' => 'Asia/Tokyo',
            'FlexibleTimeWindow' => ['Mode' => 'OFF'],
            'Target' => [
                'Arn' => config('services.aws.scaling_state_machine_arn'),
                'RoleArn' => config('services.aws.scheduler_role_arn'),
                'Input' => json_encode($input),
            ],
            // 実行後に自動削除（ワンショット）
            'ActionAfterCompletion' => 'DELETE',
        ]);
    }
}
```

#### 14-3. Lambda関数（Python）

##### auction-scale-ec2

```python
# lambda/scale_ec2.py
import boto3
import os

ec2 = boto3.client('ec2', region_name='ap-northeast-1')

# 環境変数から取得（Lambda の設定 > 環境変数で設定）
INSTANCE_ID = os.environ.get('INSTANCE_ID', 'i-xxxxxxxxxxxxxxxxx')

def handler(event, context):
    action = event['action']
    target_type = event['instance_type']

    # 現在のインスタンスタイプを確認
    current = ec2.describe_instances(InstanceIds=[INSTANCE_ID])
    current_type = current['Reservations'][0]['Instances'][0]['InstanceType']

    if current_type == target_type:
        return {'status': 'already_correct', 'instance_type': current_type}

    # EC2 停止
    ec2.stop_instances(InstanceIds=[INSTANCE_ID])
    waiter = ec2.get_waiter('instance_stopped')
    waiter.wait(InstanceIds=[INSTANCE_ID])

    # インスタンスタイプ変更
    ec2.modify_instance_attribute(
        InstanceId=INSTANCE_ID,
        InstanceType={'Value': target_type}
    )

    # EC2 起動
    ec2.start_instances(InstanceIds=[INSTANCE_ID])
    waiter = ec2.get_waiter('instance_running')
    waiter.wait(InstanceIds=[INSTANCE_ID])

    return {'status': 'success', 'instance_type': target_type}
```

##### auction-switch-config（SSM Run Command）

```python
# lambda/switch_config.py
import boto3
import os
import time

ssm = boto3.client('ssm', region_name='ap-northeast-1')

INSTANCE_ID = os.environ.get('INSTANCE_ID', 'i-xxxxxxxxxxxxxxxxx')

def handler(event, context):
    mode = event['mode']  # 'auction' or 'normal'

    # SSM Run Command で設定切り替え（SSH不要・IAM認証・監査ログ付き）
    response = ssm.send_command(
        InstanceIds=[INSTANCE_ID],
        DocumentName='AWS-RunShellScript',
        Parameters={
            'commands': [
                f'/home/ec2-user/scripts/switch-mode.sh {mode}',
            ]
        },
        TimeoutSeconds=120,
        Comment=f'Switch to {mode} mode',
    )

    command_id = response['Command']['CommandId']

    # コマンド完了を待機
    for _ in range(30):
        time.sleep(5)
        result = ssm.get_command_invocation(
            CommandId=command_id,
            InstanceId=INSTANCE_ID,
        )
        if result['Status'] in ['Success', 'Failed', 'TimedOut', 'Cancelled']:
            break

    if result['Status'] != 'Success':
        raise Exception(f"Config switch failed: {result['StandardErrorContent']}")

    return {'status': 'success', 'mode': mode, 'output': result['StandardOutputContent']}
```

# lambda/scale_rds.py
import boto3
import os

rds = boto3.client('rds', region_name='ap-northeast-1')

DB_INSTANCE_ID = os.environ.get('DB_INSTANCE_ID', 'auction-db')

# インスタンスクラスに対応するパラメータグループ
PARAM_GROUPS = {
    'db.t3.medium': 'auction-db-params-large',
    'db.t3.micro':  'auction-db-params-micro',
}

def handler(event, context):
    action = event['action']
    instance_class = event['instance_class']
    multi_az = event.get('multi_az', False)
    param_group = PARAM_GROUPS.get(instance_class, 'default.mysql8.0')

    # 現在の状態を確認
    current = rds.describe_db_instances(DBInstanceIdentifier=DB_INSTANCE_ID)
    current_instance = current['DBInstances'][0]

    if (current_instance['DBInstanceClass'] == instance_class and
        current_instance['MultiAZ'] == multi_az):
        return {'status': 'already_correct'}

    # RDS 変更（パラメータグループも同時に切り替え）
    rds.modify_db_instance(
        DBInstanceIdentifier=DB_INSTANCE_ID,
        DBInstanceClass=instance_class,
        DBParameterGroupName=param_group,
        MultiAZ=multi_az,
        ApplyImmediately=True,
    )

    return {
        'status': 'modifying',
        'target_class': instance_class,
        'multi_az': multi_az,
        'param_group': param_group,
    }

import urllib.request
import json

CHECK_URL = os.environ.get('CHECK_URL', 'https://your-domain.com/api/admin/infra/pre-scaledown-check')
INFRA_TOKEN = os.environ.get('INFRA_TOKEN', '')

class PendingWorkExists(Exception):
    pass

def handler(event, context):
    # ALB経由でLaravelのチェックエンドポイントを呼び出し
    url = CHECK_URL
    headers = {'X-Infra-Token': INFRA_TOKEN}

    req = urllib.request.Request(url, headers=headers)
    with urllib.request.urlopen(req, timeout=30) as resp:
        data = json.loads(resp.read())

    if not data.get('safe_to_scale_down', False):
        raise PendingWorkExists(
            f"Pending: {data.get('reason', 'unknown')}"
        )

    return {'status': 'safe', 'details': data}

```python
# lambda/scale_elasticache.py
import boto3
import os

elasticache = boto3.client('elasticache', region_name='ap-northeast-1')

REPLICATION_GROUP_ID = os.environ.get('REPLICATION_GROUP_ID', 'auction-redis')

def handler(event, context):
    action = event['action']
    node_type = event['node_type']
    replica_count = event.get('replica_count', 0)

    # 現在の状態を確認
    response = elasticache.describe_replication_groups(
        ReplicationGroupId=REPLICATION_GROUP_ID
    )
    group = response['ReplicationGroups'][0]
    current_node_type = group['CacheNodeType']
    current_replicas = len(group['MemberClusters']) - 1  # primary を除く

    # ノードタイプ変更
    if current_node_type != node_type:
        elasticache.modify_replication_group(
            ReplicationGroupId=REPLICATION_GROUP_ID,
            CacheNodeType=node_type,
            ApplyImmediately=True,
        )

    # レプリカ数の調整
    if replica_count > current_replicas:
        elasticache.increase_replica_count(
            ReplicationGroupId=REPLICATION_GROUP_ID,
            NewReplicaCount=replica_count,
            ApplyImmediately=True,
        )
    elif replica_count < current_replicas:
        elasticache.decrease_replica_count(
            ReplicationGroupId=REPLICATION_GROUP_ID,
            NewReplicaCount=replica_count,
            ApplyImmediately=True,
        )

    return {
        'status': 'modifying',
        'target_node_type': node_type,
        'target_replica_count': replica_count,
    }

    state = response['Reservations'][0]['Instances'][0]['State']['Name']

    if state != 'running':
        raise EC2NotReady(f'EC2 state: {state}')

    # ステータスチェックも確認（OS起動完了まで待つ）
    status_response = ec2.describe_instance_status(InstanceIds=[INSTANCE_ID])
    if not status_response['InstanceStatuses']:
        raise EC2NotReady('EC2 status check not available yet')

    instance_status = status_response['InstanceStatuses'][0]
    if (instance_status['InstanceStatus']['Status'] != 'ok' or
        instance_status['SystemStatus']['Status'] != 'ok'):
        raise EC2NotReady('EC2 status checks not passed yet')

    return {'status': 'running', 'checks': 'ok'}
```

#### 14-4. SSM を使ったEC2設定切り替え

Lambda から EC2 の設定を変更する際、SSH ではなく **SSM Run Command** を使用する。

**SSM の利点:**
| 項目 | SSH | SSM Run Command |
|------|-----|----------------|
| 認証 | SSH鍵の管理が必要 | IAMロールで自動認証 |
| ネットワーク | SG で 22番ポート開放が必要 | VPCエンドポイント or インターネット経由 |
| 監査ログ | なし（自前で用意） | CloudTrail に自動記録 |
| Lambda連携 | paramiko等のライブラリが必要 | boto3 標準で対応 |

**前提条件:**
1. EC2 に SSM Agent がインストール済み（Amazon Linux 2023 はプリインストール）
2. EC2 の IAM ロールに `AmazonSSMManagedInstanceCore` ポリシーをアタッチ

EC2 上の切り替えスクリプトは同じものを使用:

```bash
#!/bin/bash
# /home/ec2-user/scripts/switch-mode.sh
# SSM Run Command から呼び出される

MODE=$1
CONF_DIR="/home/ec2-user/configs"

if [ "$MODE" = "auction" ]; then
    sudo cp "$CONF_DIR/php-fpm-auction.conf" /etc/php-fpm.d/www.conf
    sudo cp "$CONF_DIR/supervisor-auction.ini" /etc/supervisord.d/auction.ini
elif [ "$MODE" = "normal" ]; then
    sudo cp "$CONF_DIR/php-fpm-normal.conf" /etc/php-fpm.d/www.conf
    sudo cp "$CONF_DIR/supervisor-normal.ini" /etc/supervisord.d/auction.ini
else
    echo "Usage: $0 {auction|normal}" >&2
    exit 1
fi

sudo systemctl restart php-fpm
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl restart all

echo "Switched to $MODE mode"
grep pm.max_children /etc/php-fpm.d/www.conf
sudo supervisorctl status
```

#### 14-7. Aurora Serverless v2 による RDS スケーリング不要化（将来オプション）

RDS のスケールアップ/ダウンには数分のダウンタイムが伴う。
**Aurora Serverless v2** に移行すると、RDS のスケーリングが完全に不要になる。

| 比較項目 | RDS MySQL 2モード運用 (現在) | Aurora Serverless v2 |
|---------|----------------|---------------------|
| スケーリング | 手動（ダウンタイム5〜15分） | **自動（ゼロダウンタイム）** |
| 通常時コスト (20日) | db.t3.micro **$10/月** | 0.5 ACU（最小） **$25/月** |
| オークション時コスト (10日) | db.t3.medium Multi-AZ **$43/月** | 自動スケール **$17/月** |
| **月額合計** | **~$53/月** | **~$42/月** |
| 運用負荷 | Step Functions でスケーリング | **運用ゼロ** |
| パラメータグループ管理 | 2つ必要（large用 / micro用） | **不要** |
| 移行コスト | — | スナップショット復元 + エンドポイント変更 |

> **通常時コストの注意点**: Aurora Serverless v2 の最小ACU（0.5）は常時課金される。
> ほぼアイドルの通常モード20日間でも月$25が発生し、RDS db.t3.micro の$10/月の**2.5倍**。
> しかしオークション時のコスト削減 + パラメータグループ管理不要 + ダウンタイム解消を
> 含めた総合コストでは月$11の削減。
>
> Aurora Serverless v2 にすると **Step Functions から RDS 関連の4ステップを完全に削除**でき、
> 自動化がさらにシンプルになる。MySQL 8.0 互換のため、アプリケーション変更は不要。
>
> **判断基準**:
> - コスト最優先 → 現行 RDS 2モード運用を維持
> - 運用負荷削減・ダウンタイム解消を優先 → Aurora Serverless v2 に移行（**推奨**）
