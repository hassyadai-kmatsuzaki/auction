## 1. 概要

### 1.1 フロー全体図

```
【オークション終了】
   │
   │ ★全自動で以下が実行される
   │
   ├─ 落札者フロー ──────────────────────────────────────────────────────┐
   │  ①落札                                                            │
   │  ②請求書自動生成（PDF）→ メール+LINEで自動送付                     │
   │  ③入金確認（自動消し込み）→ Thanksメール+LINE自動送信               │
   │  ④発送 → 発送通知メール+LINE自動送信                               │
   │                                                                    │
   ├─ 出品者フロー ──────────────────────────────────────────────────────┤
   │  ①落札                                                            │
   │  ②金額確定（オークション終了時に自動確定）                          │
   │  ③落札者入金確認                                                   │
   │  ④出品者振込（管理者が振込実行 → ステータス自動更新）               │
   │  ⑤支払通知書自動生成（PDF）→ メール+LINEで自動送付                 │
   │                                                                    │
   ├─ 管理側自動処理 ────────────────────────────────────────────────────┤
   │  ・入金自動消し込み（銀行データ照合）→ Slack通知                    │
   │  ・翌々日朝: 未入金リストSlack送信 + 落札者へリマインド              │
   │  ・翌々々日朝: 未入金リストSlack送信 + 落札者へリマインド + 電話リスト│
   │  ・全入金完了: Slack通知                                            │
   └────────────────────────────────────────────────────────────────────┘
```

### 1.2 自動化ポイント

| 処理 | トリガー | 自動アクション |
|------|---------|--------------|
| 請求書発行 | オークション終了 | PDF生成 → メール送信 → LINE送信 |
| 入金確認 | 銀行データ取り込み | 自動消し込み → ステータス変更 → Slack通知 → Thanks通知 |
| 未入金追いかけ | スケジュール（翌々日・翌々々日の朝） | Slack通知 → 落札者へリマインド通知 |
| 全入金完了 | 最後の入金消し込み完了時 | Slack通知 |
| 支払通知書発行 | 出品者振込完了 | PDF生成 → メール送信 → LINE送信 |

## 2. 手数料・送料の計算ロジック

### 2.1 落札者（買受者）手数料

既存ロジック: `Auction::calculateBuyerCommission()`

```
落札者手数料 = max( 落札金額合計 × 手数料率, 最低手数料 )
```

| パラメータ | デフォルト値 | システム設定キー | オークション個別設定可 |
|-----------|------------|----------------|---------------------|
| 手数料率 | **5%** | `buyer_commission_rate` | あり (`custom_fee_settings`) |
| 最低手数料 | **¥300** | `buyer_commission_min` | あり |

#### 計算例

| 落札金額合計 | 手数料率5%計算 | 最低額¥300との比較 | **適用手数料** |
|------------|-------------|-----------------|-------------|
| ¥3,000 | ¥150 | ¥150 < ¥300 | **¥300**（最低額適用） |
| ¥10,000 | ¥500 | ¥500 > ¥300 | **¥500** |
| ¥50,000 | ¥2,500 | ¥2,500 > ¥300 | **¥2,500** |

### 2.2 出品者手数料

既存ロジック: `Auction::calculateSellerCommission()`

```
出品者手数料 = max( 落札金額合計 × 手数料率, 最低手数料 )
```

| パラメータ | デフォルト値 | システム設定キー | オークション/出品者個別設定可 |
|-----------|------------|----------------|--------------------------|
| 手数料率 | **10%** | `default_commission_rate` | あり（オークション: `custom_fee_settings`、出品者: `seller_profiles.commission_rate`） |
| 最低手数料 | **¥500** | `seller_commission_min` | あり |

#### 計算例

| 落札金額合計 | 手数料率10%計算 | 最低額¥500との比較 | **適用手数料** |
|------------|--------------|-----------------|-------------|
| ¥3,000 | ¥300 | ¥300 < ¥500 | **¥500**（最低額適用） |
| ¥10,000 | ¥1,000 | ¥1,000 > ¥500 | **¥1,000** |
| ¥50,000 | ¥5,000 | ¥5,000 > ¥500 | **¥5,000** |

### 2.3 送料

既存ロジック: `SystemSetting::getShippingDefaults()`

#### 2.3.1 基本送料（地域 × サイズ）

| 地域 | 60サイズ | 80サイズ | 100サイズ |
|------|---------|---------|----------|
| 関東 | ¥800 | ¥1,000 | ¥1,200 |
| 関西 | ¥900 | ¥1,100 | ¥1,300 |
| 北海道 | ¥1,500 | ¥1,800 | ¥2,100 |
| 沖縄 | ¥1,800 | ¥2,200 | ¥2,600 |
| その他 | ¥1,000 | ¥1,200 | ¥1,500 |

#### 2.3.2 追加送料

| 項目 | 金額 | 条件 | システム設定キー |
|------|------|------|----------------|
| 梱包料 | **¥500** | 全配送 | `packaging_fee` |
| 取扱手数料 | **¥300** | 全配送 | `handling_fee` |
| 保険料 | **落札金額の3%** | 全配送 | `insurance_fee_rate` |
| クール便（夏季） | **¥300** | 6月〜9月 | `cooling_fee_summer` |
| 温度管理（冬季） | **¥300** | 12月〜2月 | `heating_fee_winter` |

#### 2.3.3 送料合計の計算式

```
送料合計 = 基本送料（地域×サイズ）
         + 梱包料（¥500）
         + 取扱手数料（¥300）
         + 保険料（落札金額 × 3%）
         + 季節料金（該当する場合）
```

#### 2.3.4 引き取り（pickup）の場合

```
送料合計 = ¥0
```

請求書上は「¥0」と表記する（行自体は表示する）。

#### 2.3.5 計算例（配送の場合）

| 条件 | 金額 |
|------|------|
| 落札金額合計 | ¥10,000 |
| 配送先 | 関東 / 60サイズ |
| 配送月 | 7月（夏季） |
| | |
| 基本送料 | ¥800 |
| 梱包料 | ¥500 |
| 取扱手数料 | ¥300 |
| 保険料（¥10,000 × 3%） | ¥300 |
| クール便（夏季） | ¥300 |
| **送料合計** | **¥2,200** |

### 2.4 プレミアム出品手数料（出品者向け）

| パラメータ | デフォルト値 | システム設定キー |
|-----------|------------|----------------|
| プレミアム出品手数料 | **¥300/件** | `premium_plan_fee` |

```
プレミアム出品費用 = プレミアム出品アイテム数 × ¥300
```

- 出品者の支払通知書にのみ記載
- プレミアム出品がない場合は行を非表示

### 2.5 既存の落札時計算ロジック（FinalizeBidAction）

落札確定時に`WonItem`に保存される値:

```php
$totalBase      = winning_price × quantity;           // 落札金額合計
$commissionAmt  = calculateBuyerCommission(totalBase); // 落札者手数料
$totalAmount    = totalBase + commissionAmt;           // 落札者支払総額（※送料は別途）
$sellerAmt      = totalBase - calculateSellerCommission(totalBase); // 出品者受取額
```

## 3. 発行時スナップショット設計

### 3.1 基本方針

手数料・送料の計算ロジック（料率・最低額・送料テーブル等）は**いつでも設定画面から変更可能**とする。ただし、**一度発行された請求書・支払通知書の金額は変更後の設定に影響されない**。

これを実現するため、請求書（Invoice）・精算（Settlement）レコードには、発行時点の全計算パラメータを**スナップショットとして保存**する。表示・再計算時は外部テーブル（`system_settings`、`custom_fee_settings`等）を参照せず、レコード内のスナップショット値を使用する。

```
【設定変更と請求書の関係】

timeline ──────────────────────────────────────────→

  設定A（手数料5%）        設定B（手数料8%に変更）
  ──────────────┤         ├─────────────────────→
                │         │
       請求書#1発行        請求書#2発行
       → 手数料5%で        → 手数料8%で
         スナップショット保存  スナップショット保存
       → 以後も5%で表示     → 以後も8%で表示
```

### 3.2 スナップショット対象パラメータ

#### 3.2.1 請求書（invoices）に保存するスナップショット

| カラム名 | 型 | 説明 |
|---------|------|------|
| `snapshot_buyer_commission_rate` | decimal(5,2) | 発行時の落札者手数料率（%） |
| `snapshot_buyer_commission_min` | integer | 発行時の落札者最低手数料（円） |
| `snapshot_shipping_rates` | json | 発行時の送料テーブル（地域×サイズ） |
| `snapshot_packaging_fee` | integer | 発行時の梱包料（円） |
| `snapshot_handling_fee` | integer | 発行時の取扱手数料（円） |
| `snapshot_insurance_fee_rate` | decimal(5,2) | 発行時の保険料率（%） |
| `snapshot_cooling_fee_summer` | integer | 発行時のクール便料金（円） |
| `snapshot_heating_fee_winter` | integer | 発行時の温度管理料金（円） |
| `snapshot_has_invoice_registration` | boolean | 発行時の落札者インボイス登録状態 |
| `snapshot_invoice_registration_number` | string | 発行時の運営会社登録番号 |
| `snapshot_fee_source` | string | 設定の出所（`system_default` / `auction_custom`） |

#### 3.2.2 精算（settlements）に保存するスナップショット

| カラム名 | 型 | 説明 |
|---------|------|------|
| `snapshot_seller_commission_rate` | decimal(5,2) | 発行時の出品者手数料率（%） |
| `snapshot_seller_commission_min` | integer | 発行時の出品者最低手数料（円） |
| `snapshot_premium_plan_fee` | integer | 発行時のプレミアム出品手数料（円/件） |
| `snapshot_shipping_rates` | json | 発行時の送料テーブル（地域×サイズ） |
| `snapshot_packaging_fee` | integer | 発行時の梱包料（円） |
| `snapshot_handling_fee` | integer | 発行時の取扱手数料（円） |
| `snapshot_insurance_fee_rate` | decimal(5,2) | 発行時の保険料率（%） |
| `snapshot_cooling_fee_summer` | integer | 発行時のクール便料金（円） |
| `snapshot_heating_fee_winter` | integer | 発行時の温度管理料金（円） |
| `snapshot_has_invoice_registration` | boolean | 発行時の出品者インボイス登録状態 |
| `snapshot_seller_invoice_number` | string | 発行時の出品者インボイス登録番号 |
| `snapshot_fee_source` | string | 設定の出所（`system_default` / `auction_custom` / `seller_override`） |

### 3.3 設定の優先順位（発行時に解決してスナップショットに保存）

```
① オークション個別設定（custom_fee_settings / custom_shipping_settings）
  ↓ なければ
② 出品者個別設定（seller_profiles.commission_rate）※出品者手数料のみ
  ↓ なければ
③ システムデフォルト設定（system_settings）
```

発行時にこの優先順位を解決し、最終的に適用された値をスナップショットとして保存する。どの設定が使われたかは `snapshot_fee_source` に記録する。

### 3.4 スナップショットの利用ルール

| シーン | 参照先 |
|-------|-------|
| 請求書PDF生成（初回発行） | スナップショット値を計算して保存し、同時にPDF生成 |
| 請求書PDF再表示・再ダウンロード | レコード内のスナップショット値のみを使用 |
| 請求書の再発行（管理者操作） | **新しいスナップショットを取得**して新レコードを作成（旧レコードは `cancelled` ステータスで保持） |
| 支払通知書PDF生成 | 精算レコード内のスナップショット値のみを使用 |
| 管理画面での金額確認 | レコード内のスナップショット値のみを表示 |
| 設定変更後の既存請求書 | **影響なし**（スナップショットが保存済みのため） |

### 3.5 実装上の注意点

1. **計算サービスの二重化**:
   - `InvoiceCalculator::calculate()` — 現在の設定から計算（新規発行時に使用）
   - `InvoiceCalculator::recalculateFromSnapshot($invoice)` — スナップショットから再計算（表示時に使用）
   - ※通常、表示時は保存済みの合計値をそのまま使うため、再計算は監査・検証用途

2. **マイグレーション時の注意**: 既存の `WonItem` に対して遡及的にスナップショットを作成する場合は、マイグレーション実行時点の設定値を使用する（過去の設定値は復元不可能なため）

3. **JSON型カラムのバリデーション**: `snapshot_shipping_rates` 等のJSONカラムは、保存時にスキーマバリデーションを行い、必要なキーが全て存在することを保証する

## 4. インボイス制度対応

### 4.1 概要

適格請求書発行事業者（インボイス登録済み）の場合、消費税の仕入税額控除が適用されるため、手数料の扱いが異なる。

### 4.2 必要なデータ

| 対象 | フィールド | 説明 |
|------|----------|------|
| 出品者 | `seller_profiles.invoice_registration_number` | 適格請求書発行事業者番号（T+13桁） |
| 出品者 | `seller_profiles.has_invoice_registration` | インボイス登録有無フラグ |
| 落札者 | `users.invoice_registration_number` | 適格請求書発行事業者番号 |
| 落札者 | `users.has_invoice_registration` | インボイス登録有無フラグ |
| 運営会社 | システム設定 | 運営会社の適格請求書発行事業者番号 |

### 4.3 請求書への影響（落札者向け）

| 落札者のインボイス登録 | 手数料の表示 | 割引 |
|---------------------|------------|------|
| **あり** | 手数料を税抜・消費税で分けて表示 | 割引行を表示（仕入税額控除相当の割引） |
| **なし** | 手数料を税込で表示 | 割引行を**非表示** |

### 4.4 支払通知書への影響（出品者向け）

| 出品者のインボイス登録 | 手数料の表示 | 割引 |
|---------------------|------------|------|
| **あり** | 手数料を税抜・消費税で分けて表示 | 割引行を表示 |
| **なし** | 手数料を税込で表示 | 割引行を**非表示** |

### 4.5 請求書・支払通知書の法定記載事項

インボイス登録事業者が発行する適格請求書に必要な記載事項:

- 適格請求書発行事業者の氏名または名称
- 適格請求書発行事業者の登録番号
- 取引年月日
- 取引内容
- 税率ごとに区分した対価の額および適用税率
- 税率ごとに区分した消費税額
- 書類の交付を受ける事業者の氏名または名称

## 5. 落札者フロー

### 5.1 ステータス遷移

```
①落札（pending）
  ↓ [自動] オークション終了トリガー
②請求書発行（invoiced）
  ↓   PDF自動生成 → メール自動送信 → LINE自動送信
  ↓ [自動] 入金自動消し込み or [手動] 管理者確認
③入金確認（paid）
  ↓   Slack自動通知 → Thanksメール自動送信 → LINE自動送信
  ↓ [自動/手動] 出品者が発送登録
④発送（shipped → completed）
      発送通知メール自動送信 → LINE自動送信
```

| ステータス | 値 | トリガー | 自動アクション |
|-----------|-----|---------|-------------|
| 落札 | `pending` | 入札成立 | 落札通知（メール+LINE） |
| 請求書発行 | `invoiced` | オークション終了 | PDF生成 → メール送信 → LINE送信 |
| 入金確認 | `paid` | 自動消し込み/手動確認 | Slack通知 → Thanksメール → LINE |
| 発送済み | `shipped` | 出品者発送登録 | 発送通知メール → LINE |
| 完了 | `completed` | 管理者確認 | - |

### 5.2 請求書（Invoice）

#### 5.2.1 自動生成トリガー

```

  ↓
```

#### 5.2.3 請求書の金額計算式

```
① 小計         = Σ（各アイテムの winning_price × quantity）
② 手数料       = max（小計 × buyer_commission_rate, buyer_commission_min）
③ 割引         = インボイス登録ありの場合のみ計算（仕入税額控除相当）
④ 送料         = 配送の場合: 基本送料 + 梱包料 + 取扱手数料 + 保険料 + 季節料金
                  引き取りの場合: ¥0
──────────────────────────────────────────────────
合計金額 = ① + ② - ③ + ④
```

### 5.3 入金処理

#### 5.3.1 自動消し込みフロー

```
銀行入金データCSV取り込み（管理画面 or APIバッチ）
  ↓
振込名義 + 金額で請求書と自動照合
  ↓ [一致]
  ├─ WonItem.payment_status → paid に自動更新
  ├─ Invoice.status → paid に自動更新
  ├─ Slack通知: 「{落札者名}さんの入金確認（¥{金額}）」
  ├─ 落札者へThanksメール自動送信
  ├─ 落札者へThanks LINE自動送信
  ├─ 出品者のステータス → buyer_paid に自動更新
  └─ 全入金完了チェック → 完了ならSlack通知
  ↓ [不一致]
  └─ 管理者が手動で紐付け
```

## 6. 出品者フロー

### 6.1 ステータス遷移

```
①落札（won）
  ↓ [自動] 商品が落札された時点で自動設定
②金額確定（amount_confirmed）
  ↓ [自動] オークション終了時に手数料・送料を含む最終金額を自動確定
③落札者入金確認（buyer_paid）
  ↓ [自動] 落札者の入金消し込み完了時に自動更新
④出品者振込（transferred）
  ↓ [手動→自動] 管理者が振込実行 → ステータス自動更新
⑤支払通知書送付（notified）
```

| ステータス | 値 | トリガー | 自動アクション |
|-----------|-----|---------|-------------|
| 落札 | `won` | 入札成立 | 出品者へ売却通知（メール+LINE） |
| 金額確定 | `amount_confirmed` | オークション終了 | 最終金額を自動計算・確定 |

| 出品者振込 | `transferred` | 管理者振込実行 | ステータス自動更新 |
| 支払通知書送付 | `notified` | 振込完了 | PDF自動生成 → メール自動送信 → LINE自動送信 |

```

振込金額 = ① - ② + ③ - ④ - ⑤
```

## 7. 自動処理・スケジュールタスク

### 7.1 オークション終了時（即時自動実行）

```
LiveController::finish() 実行
  ↓
1. 全WonItemの最終金額確定
  ↓
2. 現時点の手数料・送料設定をスナップショットとして取得
   （設定の優先順位を解決: オークション個別 > 出品者個別 > システムデフォルト）
  ↓
3. 落札者単位で請求書(Invoice)レコード自動作成 ★スナップショット値を保存
  ↓
4. 出品者単位で精算(Settlement)レコード自動作成 ★スナップショット値を保存
  ↓
5. 請求書PDF自動生成（スナップショット値から計算・描画）
  ↓
6. 請求書PDFを落札者にメール自動送信
  ↓
7. 請求書PDFを落札者にLINE自動送信
  ↓
8. WonItem.payment_status → invoiced に自動更新
  ↓
9. Settlement.status → amount_confirmed に自動更新
```

### 7.2 入金消し込み時（自動 or 手動トリガー）

```
入金データ取り込み → 自動照合 → 一致
  ↓
1. WonItem.payment_status → paid
  ↓
2. Invoice.status → paid
  ↓
3. Settlement.status → buyer_paid
  ↓
4. Slack通知: 個別入金確認
  ↓
5. 落札者へThanksメール自動送信
  ↓
6. 落札者へThanks LINE自動送信
  ↓
7. 出品者へ入金確認通知（メール+LINE）自動送信
  ↓
8. 全入金完了チェック → 完了ならSlack通知
```

### 7.3 出品者振込時（管理者操作トリガー）

```
管理者が振込完了を記録
  ↓
1. Settlement.status → transferred
  ↓
2. 支払通知書PDF自動生成
  ↓
3. 支払通知書PDFを出品者にメール自動送信
  ↓
4. 支払通知書PDFを出品者にLINE自動送信
  ↓
5. Settlement.status → notified
```

### 7.4 スケジュールタスク（Cronジョブ）

|-------|-------------|---------|

| `CheckUrgentUnpaidInvoices` | 毎朝9:00 | オークション実施日の翌々々日に該当するものを検出 → Slack緊急未入金リスト送信 + 落札者リマインド（メール+LINE）+ 電話対応リスト |
