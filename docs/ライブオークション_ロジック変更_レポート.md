## 1. 概要

ライブオークションの入札ロジックを「ON/OFFトグル型」から「プッシュ型 × 指値優先」に変更する。
本レポートは、既存ロジックと変更後ロジックを整理し、差分と影響範囲を明確にするものである。

### 変更の要旨

| 項目 | 既存 | 変更後 |
|------|------|--------|
| 入札方式 | ON/OFFトグル | プッシュ型（指値ベース） |
| 優先順位 | なし | 指値金額順 → 同額は先着順 |
| 価格進行 | 1段階ずつ上昇 | 指値間スキップあり |
| 現在価格の意味 | 今の価格 | 次の金額 |
| 入札状態の表示 | ON/OFFのみ | 落札候補かどうかを文字表示 |

## 2. 既存ロジック（現行システム）

### 2.1 入札方式: ON/OFF トグル型

参加者は各商品に対して「入札する（ON）」「入札しない（OFF）」を切り替えるだけのシンプルな方式。

- ONにしている**全員が「入札参加者」として同等**に扱われる
- 先着や金額による優先順位は**存在しない**
- 入札者数のみが価格上昇の判定基準

### 2.2 価格上昇ルール

| 条件 | 動作 |
|------|------|
| 入札者 0〜1人 | 通常カウントダウン（デフォルト10秒） |
| 入札者 2人以上 | 競合カウントダウン（デフォルト1秒） |
| カウントダウン0到達 + 入札者2人以上 | 価格上昇 → カウントダウンリセット |
| カウントダウン0到達 + 入札者1人 | **落札確定** |
| カウントダウン0到達 + 入札者0人 | **不成立（unsold）** |

**価格上昇の計算式:**

```
上昇額 = MAX(現在価格 × 上昇率, 最低上昇額)
新価格 = 現在価格 + 上昇額

デフォルト値:
  上昇率 = 10%
  最低上昇額 = 50円
```

**例: 1,000円スタートの場合の価格推移:**

```
1,000円 → 1,100円 → 1,210円 → 1,331円 → 1,464円 → ...
（毎回10%ずつ上昇）
```

### 2.3 指値（上限価格）の動作

| タイミング | 動作 |
|-----------|------|
| オークション開始前に指値設定 | 商品がレーンに来たら**自動で入札ON** |
| オークション中に指値設定 | 現在価格 < 指値 なら**即座に入札ON** |
| 価格上昇後 | 現在価格 ≥ 指値 のユーザーを**自動で入札OFF** |
| 指値設定時に現在価格 ≥ 指値 | 入札せず即発動済みとする |

**重要な特性:**

- 指値はあくまで「自動OFF」のセーフティ機能
- 指値の金額に関係なく、開始価格から1段階ずつ上昇する（**スキップなし**）
- 全員が同等の入札者として扱われるため、指値を早く入れたことに特別な意味はない

### 2.4 落札の決定方法

```
カウントダウン終了
  ├── 入札者 0人 → 不成立（unsold）
  ├── 入札者 1人 → その人が落札（sold）
  └── 入札者 2人以上 → 価格上昇 → カウントダウンリセット → 繰り返し
```

落札者は「最後の1人」であり、誰が落札者になるかは入札者が自発的にOFFにするか、指値による自動OFFで決まる。

### 2.5 現在価格の表示

- 画面に表示される「現在価格」= **今の確定した価格**
- 価格上昇が発生した時点で更新される

### 2.6 カウントダウンの仕組み

- サーバー側で0.5秒間隔のジョブ（`ProcessAuctionCountdownJob`）が全レーンを処理
- Redisキャッシュでカウントダウン状態を管理
- WebSocket（Pusher）で0.5秒ごとにフロントエンドに配信
- フロントエンドは `Math.ceil()` で整数秒表示

### 2.7 レーン進行

```
商品がliveに → pre_bid（入札開始待機）→ bidding（入札カウントダウン）
  → 落札 or 不成立 → 次の商品へ → pre_bid → ...
  → 商品がなくなったらレーン終了
  → 全レーン終了でオークション自動終了
```

### 2.8 既存ロジックの関連ファイル

| ファイル | 役割 |
|---------|------|
| `app/Services/CountdownService.php` | カウントダウン管理、価格上昇、指値チェック、落札判定 |
| `app/Actions/Bid/JoinBidAction.php` | 入札ON処理 |
| `app/Actions/Bid/LeaveBidAction.php` | 入札OFF処理 |

| `app/Jobs/ProcessAuctionCountdownJob.php` | 0.5秒間隔のカウントダウン処理 |
| `app/Models/BidParticipant.php` | 入札参加者モデル |
| `app/Models/BidLimitPrice.php` | 指値モデル |
| `resources/ts/pages/participant/AuctionLive.tsx` | ライブ画面UI |

## 3. 変更後ロジック（新システム）

### 3.1 入札方式: プッシュ型 × 指値優先

参加者は**指値（上限価格）を設定することで入札に参加**する。
指値の金額と設定時刻が優先順位の基準となる。

**基本原則:**

- 指値が**早い人が優先**される
- 指値金額が**高い人が上位**
- 同額の場合は**先に指値を入れた人が優先**

### 3.2 優先順位ルール

#### ルール1: 指値が同じ2名の場合

先に指値を入れた方が優先される。

```
Aさん: 指値 1,000円（10:00に設定）
Bさん: 指値 1,000円（10:05に設定）
→ Aさんが優先
```

#### ルール2: 複数人いるとき

一番早く入札した人が次の金額に繰り上がる。
繰り上がった後は、他の人が入札してきたら、その中で最も早い人が次に繰り上がっていく。

#### ルール3: 途中で指値が複数人入った場合

そこまでスキップされる。

### 3.3 金額帯別カスタム上昇幅（価格インクリメントティア）

**旧方式（廃止）:** `現在価格 × 上昇率（10%）` の固定計算

**新方式:** 金額帯ごとに上昇金額をカスタム設定できるテーブル方式

#### 3.3.1 上昇幅テーブルの構造

管理画面から**オークションごとに**設定可能な金額帯別上昇幅テーブル:

```
price_increment_tiers（金額帯別上昇幅テーブル）:

| 下限金額（from_price） | 上限金額（to_price） | 上昇金額（increment_amount） |
|----------------------|--------------------|-----------------------------|
| 0                    | 999                | 50                          |
| 1,000                | 4,999              | 100                         |
| 5,000                | 9,999              | 500                         |
| 10,000               | 49,999             | 1,000                       |
| 50,000               | ∞                  | 5,000                       |
```

**例: 1,000円スタートの場合の価格推移:**

```
1,000円 → 1,100円 → 1,200円 → ... → 4,900円 → 5,000円
→ 5,500円 → 6,000円 → ... → 9,500円 → 10,000円
→ 11,000円 → 12,000円 → ...
```

#### 3.3.2 設定の優先順位

```
1. オークション個別のカスタム設定（custom_auction_settings.price_increment_tiers）
2. システムデフォルト設定（system_settings テーブルの default_price_increment_tiers）
3. フォールバック: 100円固定
```

#### 3.3.3 管理画面での設定

- **システム設定画面（Settings）:** デフォルトの金額帯別上昇幅テーブルを設定
- **オークション作成/編集画面（AuctionForm）:** オークションごとにカスタムの金額帯別上昇幅テーブルを設定（カスタム設定ON時）
- 行の追加・削除が可能
- バリデーション: 金額帯が重複しないこと、下限 < 上限であること

### 3.4 価格スキップルール

複数人の指値が入っていて金額がバラバラの場合、**競合している上位1人目と2人目の指値のところまでスキップ**され、そこからスタートする。

**スキップの計算:**

```
指値を金額の降順でソート（同額は設定時刻の昇順）
  → 上位1位の指値と上位2位の指値を特定
  → 2位の指値付近まで価格をスキップ
  → そこから通常の価格上昇を開始
```

**例:**

```
Aさん: 指値 5,000円
Bさん: 指値 3,000円
Cさん: 指値 1,500円

上位1位: Aさん（5,000円）
上位2位: Bさん（3,000円）

→ 3,000円付近までスキップしてスタート
```

### 3.5 途中参加時のスキップ

オークション進行中に新しい指値が入った場合も、スキップが発生する。

**例:**

```
現在: Aさんのみ指値 1,000円で進行中（現在価格 1,100円）
途中: Bさんが指値 3,000円で参加

→ 上位1位: Bさん（3,000円）、上位2位: Aさん（1,000円）
→ 既に1,100円なのでスキップは発生しない（1,000円は超過済み）
→ 通常の価格上昇が継続
→ Aさんの指値到達後、Bさんが落札候補に
```

### 3.6 2段階カウントダウンシステム

**旧方式（廃止）:** 単一カウントダウン（通常10秒 / 競合1秒）

**新方式:** 入札時に即座に価格上昇し、2段階のカウントダウンを経て落札を決定

#### 3.6.1 カウントダウンの種類と設定範囲

| カウントダウン種別 | 設定範囲 | デフォルト | 説明 |
|-------------------|---------|-----------|------|
| オークション開始待機時間 | 0秒〜1時間 | 10秒 | オークション開始前のカウントダウン |
| フリーズ（誤タップ防止）カウント | 0.5秒〜10秒 | 1秒 | 入札直後の誤タップ防止期間 |
| 落札カウント | 0.5秒〜10秒 | 5秒 | 入札受付カウントダウン |
| 商品開始毎カウント | 0.5秒〜10秒 | 5秒 | 次の商品表示後の待機時間（既存の item_switch_delay_seconds） |
| 落札確定後カウント | 0.5秒〜10秒 | 2秒 | 落札確定後の表示時間 |
| 商品アップロード期限 | 日時指定 | - | 出品者のアップロード締切 |

#### 3.6.2 入札→価格上昇→カウントダウンのフロー

```
入札者が入札ボタンを押す
  │
  ├── 入札者が2人以上になった場合
  │     │
  │     ▼
  │   【即座に価格上昇】（金額帯別上昇幅テーブルに基づく）
  │     │
  │     ▼
  │   【フリーズカウントダウン開始】（0.5秒〜10秒、カスタム設定可能）
  │     │  ※ この間、入札ボタンはグレーアウト（誤タップ防止）
  │     │  ※ 円形の砂時計アニメーション表示
  │     │
  │     ▼
  │   【落札カウントダウン開始】（0.5秒〜10秒、カスタム設定可能）
  │     │  ※ 入札ボタンが有効化される
  │     │
  │     ├── 誰かが入札した場合 → 【即座に価格上昇】に戻る
  │     │
  │     └── 誰も入札しなかった場合
  │           │
  │           ▼
  │         【落札確定】最後の入札者が落札
  │
  └── 入札者が1人以下の場合
        │
        ▼
      【落札カウントダウン】（通常の落札カウント）
        │
        ├── 入札者1人 + カウントダウン終了 → 落札確定
        └── 入札者0人 + カウントダウン終了 → 不成立（unsold）
```

#### 3.6.3 具体シナリオ: 入札→即時上昇→2段階カウントダウン

```
前提:
  Aさんの指値: 1,000円、Bさんの指値: 2,000円
  金額帯: 1,000円〜4,999円 → 100円ずつ上昇
  フリーズカウント: 1秒、落札カウント: 5秒

1. 指値に基づき、1,100円でAさんが離脱した状態からスタート
   → Bさんが1,100円で落札権利を保持

2. Cさんが入札ボタンを押す
   → 1,100円が2人（Bさん+Cさん）になる
   → 【即座に】金額が1,200円に上昇
   → Cさんが1,200円の落札権利を保持

3. フリーズカウントダウン開始（1秒間）
   → 入札ボタンがグレーアウト（誤タップ防止）
   → 円形砂時計アニメーション表示

4. フリーズカウントダウン終了 → 落札カウントダウン開始（5秒間）
   → 入札ボタンが有効化される

5-A. 誰も入札しない場合:
   → カウントダウン終了 → Cさんが1,200円で落札

5-B. Bさんが入札した場合:
   → 【即座に】金額が1,300円に上昇
   → Bさんが1,300円の落札権利を保持
   → フリーズカウントダウン開始（1秒間）
   → 落札カウントダウン開始（5秒間）
   → 誰も入札しなければ → Bさんが1,300円で落札
```

### 3.7 落札の決定方法

基本的な落札条件は既存と同じだが、**「誰が落札者か」の決定に優先順位が関与**する。

```
カウントダウン終了
  ├── 入札者 0人 → 不成立（unsold）
  ├── 入札者 1人 → その人が落札（sold）
  └── 入札者 2人以上 → 即座に価格上昇 → フリーズCD → 落札CD → 繰り返し
```

### 3.8 具体シナリオ: 同額指値の進行

ユーザー提示のシナリオに基づく詳細フロー:

```
Aさん: 指値 1,000円（先に設定）
Bさん: 指値 1,000円（後に設定）

1. Aさんが先に指値を入れたため、Aさんが優先
2. オークション開始 → 1,000円からスタート

3. 1,000円の時点:
   - Aさん: 入札中（落札候補）← 先着優先
   - Bさん: 入札中（落札候補ではない）

4. 価格上昇 → 1,100円:
   - Aさんの指値（1,000円）に到達 → Aさん離脱
   - Bさんの指値（1,000円）にも到達しているが、
     Bさんは「繰り上がり」で入札中の状態を維持

   ※ ここの解釈: 1,100円になったタイミングでは
     Aさんだけが残っていた（Aさん優先のため）

5. Bさんが再度参加（再入札）

6. 価格上昇 → 1,200円:
   - Bさんが入札中（落札者の権利を持った状態）

7. 誰も参加しなければ → Bさんが落札（1,200円で確定）
```

### 3.9 現在価格の表示ルール

**現在価格 = 次の金額（次のステップの価格）**

```
例:
  指値1,000円のユーザーと指値2,000円のユーザーがいる場合
  → 画面上の「現在価格」には「1,200円」が表示される
  （1,000円から金額帯テーブルに基づき100円上昇した次の価格）
```

これにより、参加者は「次にいくらになるか」を即座に把握できる。

### 3.10 入札状態の表示（ゲーミフィケーション）

自分が入札中であるか、落札対象であるかが**常に文字で表示**される。

| 状態 | 表示テキスト例 |
|------|--------------|
| 落札候補（最優先） | 「🏆 あなたが現在の落札候補です」 |
| 入札中（候補ではない） | 「📢 入札中です — 価格上昇中...」 |
| 指値到達で離脱 | 「⚠️ 上限価格に達しました」 |
| 未参加 | 「入札していません」 |
| 落札確定 | 「🎉 落札おめでとうございます！」 |

ゲーミフィケーション要素として、自分の立ち位置がリアルタイムで変化することで臨場感を演出する。

## 4. 既存 vs 変更後 比較表

| 観点 | 既存（ON/OFFトグル型） | 変更後（プッシュ型×指値優先） |
|------|----------------------|---------------------------|
| **入札方法** | ON/OFFボタンのトグル | 指値（金額）を設定して参加 |
| **優先順位** | なし（全員同等） | 金額高い順 → 同額は先着順 |
| **価格スキップ** | なし（1段階ずつ上昇） | 上位1位と2位の指値間までスキップ |
| **途中参加時** | 即座にONになるだけ | 指値に応じてスキップ判定が再計算 |
| **落札者の決定** | 最後の1人が残った時点 | 最後の1人が残った時点（同じ） |
| **現在価格の意味** | 今の確定価格 | 次の金額（次ステップ） |
| **入札状態の表示** | ON/OFFのみ | 落札候補かどうかを文字で表示 |
| **ゲーミフィケーション** | なし | 入札状態の文字表示で臨場感 |
| **指値の役割** | セーフティ（自動OFF） | 入札参加の手段 + 優先順位の基準 |
| **カウントダウン** | 0〜1人: 10秒 / 2人以上: 1秒 | 2段階: フリーズCD（0.5〜10秒）→ 落札CD（0.5〜10秒） |
| **価格上昇の計算** | 現在価格 × 10%（最低50円） | 金額帯別カスタム上昇幅テーブル（管理画面から設定可能） |
| **価格上昇のタイミング** | カウントダウン終了後 | 入札があった瞬間に即座に上昇 |
| **誤タップ防止** | なし | フリーズカウントダウン（ボタングレーアウト + 砂時計） |
| **カウントダウン設定** | 管理画面で固定値のみ | オークションごとにカスタム設定可能 |

## 5. 具体的なシナリオ比較

### シナリオ1: 3人が異なる指値で参加

**条件:** 商品X、開始価格 1,000円

| 参加者 | 指値 | 設定順 |
|--------|------|--------|
| Aさん | 5,000円 | 1番目 |
| Bさん | 3,000円 | 2番目 |
| Cさん | 1,500円 | 3番目 |

#### 既存ロジックの場合

```
1. 商品Xがレーンに → 3人とも自動で入札ON
2. 入札者3人 → 競合カウントダウン（1秒）
3. 1段階ずつ上昇:
   1,000 → 1,100 → 1,210 → 1,331 → 1,464 → 1,611（Cさん指値到達、自動OFF）
4. 入札者2人 → 引き続き上昇:
   1,772 → 1,949 → 2,144 → 2,358 → 2,594 → 2,853 → 3,138（Bさん指値到達、自動OFF）
5. 入札者1人（Aさん）→ 通常カウントダウン（10秒）
6. 誰も参加しなければ → Aさんが3,138円で落札

所要時間: 約12回の価格上昇 × 1秒 + 10秒 = 約22秒
```

#### 変更後ロジックの場合

```
1. 指値ランキング: 1位 Aさん（5,000円）、2位 Bさん（3,000円）、3位 Cさん（1,500円）
2. 上位1位と2位の間 → 3,000円付近までスキップ
3. 3,000円からスタート → Bさん指値到達 → Bさん離脱
4. Cさんは既に1,500円で指値到達済み → 不参加
5. 入札者1人（Aさん）→ カウントダウン
6. 誰も参加しなければ → Aさんが落札

所要時間: 大幅に短縮
```

### シナリオ2: 同額指値の2人

**条件:** 商品X、開始価格 1,000円

| 参加者 | 指値 | 設定順 |
|--------|------|--------|
| Aさん | 1,000円 | 1番目（先） |
| Bさん | 1,000円 | 2番目（後） |

#### 既存ロジックの場合

```
1. 2人とも自動で入札ON
2. 入札者2人 → 競合カウントダウン → 価格上昇
3. 1,100円 → 両者の指値（1,000円）到達 → 2人とも自動OFF
4. 入札者0人 → 不成立（unsold）
```

#### 変更後ロジックの場合

```
1. Aさんが先に指値 → Aさんが優先
2. 1,000円からスタート（Aさんが落札候補）
3. 1,100円に上昇 → Aさんだけが残っている状態
4. Bさんが再度参加
5. 1,200円 → Bさんが入札中（落札者の権利を持った状態）
6. 誰も参加しなければ → Bさんが1,200円で落札
```

### シナリオ3: 途中で指値が入る

**条件:** 商品X、開始価格 1,000円

#### 変更後ロジックの場合

```
1. Aさんが指値1,000円で参加 → 1,000円からスタート
2. Aさん1人のみ → 通常カウントダウン中
3. 途中でBさんが指値2,000円、Cさんが指値1,500円で参加
4. 指値ランキング再計算:
   1位 Bさん（2,000円）、2位 Cさん（1,500円）、3位 Aさん（1,000円）
5. 1,500円付近までスキップ
6. Aさんは指値到達済み → 離脱
7. BさんとCさんで競合 → 価格上昇
8. Cさん指値到達 → Bさんが落札候補
```

## 7. 設計上の重要ポイント

### 7.1 金額帯別上昇幅テーブルの設計

**決定事項:**
- `price_increment_tiers` として JSON 形式で管理
- システムデフォルト: `system_settings` テーブルの `default_price_increment_tiers` キー
- オークション個別: `auctions.custom_auction_settings` 内の `price_increment_tiers` キー
- 管理画面から行の追加・削除・編集が可能

**テーブル構造:**
```json
[
  { "from_price": 0, "to_price": 999, "increment_amount": 50 },
  { "from_price": 1000, "to_price": 4999, "increment_amount": 100 },
  { "from_price": 5000, "to_price": 9999, "increment_amount": 500 },
  { "from_price": 10000, "to_price": 49999, "increment_amount": 1000 },
  { "from_price": 50000, "to_price": null, "increment_amount": 5000 }
]
```

### 7.2 2段階カウントダウンの設計

**決定事項:**
- フリーズ（誤タップ防止）カウントダウンと落札カウントダウンの2段階
- 各カウントダウンの秒数はオークションごとにカスタム設定可能
- フリーズ中は入札ボタンをグレーアウトし、円形砂時計アニメーションを表示

**カウントダウン設定キー:**
| 設定キー | 説明 | 範囲 | デフォルト |
|---------|------|------|-----------|
| `freeze_countdown_seconds` | フリーズ（誤タップ防止）カウント | 0.5〜10秒 | 1秒 |
| `bid_countdown_seconds` | 落札カウント | 0.5〜10秒 | 5秒 |
| `item_switch_delay_seconds` | 商品開始毎カウント | 0.5〜10秒 | 5秒 |
| `post_sale_display_seconds` | 落札確定後カウント | 0.5〜10秒 | 2秒 |
| `auction_start_countdown_seconds` | オークション開始待機時間 | 0〜3600秒 | 10秒 |

**キャッシュ状態のフェーズ:**
```
phase: 'pre_bid' | 'freeze' | 'bidding' | 'post_sale'
```

### 7.3 価格スキップロジックの設計

**課題:** 上位1位と2位の指値を特定し、どこまでスキップするかを正確に計算する必要がある。

**検討事項:**
- スキップ先の価格は「2位の指値ちょうど」か「2位の指値を超えた次の段階」か
- スキップ中の価格履歴（PriceEvent）をどう記録するか
- スキップ時のWebSocketイベントの送信タイミング

### 7.4 優先順位の管理

**課題:** 指値金額 × 設定時刻のソートと、繰り上がり時の再計算をリアルタイムで行う必要がある。

**検討事項:**
- 優先順位はDBに永続化するか、毎回計算するか
- 繰り上がり時の通知タイミング
- 同時に複数人が指値を設定した場合の競合制御

### 7.5 途中参加時のスキップ

**課題:** リアルタイムで新しい指値が入った際に、即時スキップ処理を行う必要がある。

**検討事項:**
- カウントダウン進行中にスキップが発生した場合のカウントダウンリセット
- スキップにより指値到達となるユーザーの自動離脱処理
- フロントエンドでの価格ジャンプの表示演出

### 7.6 現在価格の意味の変更

**課題:** 「今の価格」から「次の金額」への表示変更は、UIとバックエンドの両方に影響する。

**検討事項:**
- DBに保存する `current_price` は「今の価格」のまま、表示用に「次の金額」を計算するか
- それとも `current_price` 自体を「次の金額」にするか
- 落札価格の確定時にどの値を使うか

### 7.7 ゲーミフィケーション要素

**課題:** 入札状態の文字表示をリアルタイムで更新し、臨場感を演出する。

**検討事項:**
- 落札候補者の変更をどの頻度でブロードキャストするか
- 他の参加者に「誰が落札候補か」を見せるか（匿名性の観点）
- アニメーションやサウンドエフェクトの検討

### 7.8 既存の入札ON/OFF機能との互換性

**課題:** 既存の「入札ON/OFF」ボタンを廃止するか、指値設定UIに統合するか。

**検討事項:**
- 指値を設定せずに「とりあえず参加」するユースケースは残すか
- 指値なしの参加者は最低優先順位として扱うか
- 既存のお気に入り連動（指値設定 → お気に入り自動追加）への影響

## 付録: 用語定義

| 用語 | 定義 |
|------|------|
| **プッシュ型** | システムが価格を自動的に押し上げていく方式 |
| **指値** | 参加者が設定する上限価格。入札参加の意思表示でもある |
| **スキップ** | 不要な価格帯を飛ばして、競合が発生する価格帯から開始すること |
| **繰り上がり** | 上位の入札者が離脱した際に、次の入札者が落札候補になること |
| **落札候補** | 現時点で最も優先順位が高い入札者。他に競合者がいなければ落札する |
| **ゲーミフィケーション** | ゲーム的要素を取り入れてユーザー体験を向上させること |
