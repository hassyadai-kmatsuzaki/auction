## 1. 概要

### 1.1 目的

本仕様書では以下の3点を統一的に改善する。

| # | 項目 | 目的 |
|---|------|------|
| 1 | ルーティングガード | 認証・認可を確実にし、不正アクセスを防止する |
| 2 | 404統一 | API・フロントエンド双方で一貫した404体験を提供する |
| 3 | バリデーションメッセージ統一 | バックエンド・フロントエンドで統一的なエラーメッセージを表示する |

### 1.2 現状の問題点

#### ルーティングガード
- ログイン後に「元のページ」に戻る機能がない（`location.state.from` が未使用）
- 認証済みユーザーが `/login` や `/register` にアクセスできてしまう
- 権限不足時に `/` にリダイレクトされ、ロールによる再リダイレクトが発生
- `Login.tsx` に `console.log` が残存

#### 404統一
- フロントエンドのルート404は `NotFound` コンポーネントで処理されている
- バックエンドAPI の 404（`findOrFail` 等）はフロントエンドで汎用エラーメッセージとして表示される
- axios インターセプターに 404 のハンドリングがない
- Laravelの例外ハンドラーが未カスタマイズ（デフォルトのまま）

#### バリデーションメッセージ
- バックエンドで `FormRequest`（3クラス）/ `Validator::make()`（多数）/ `$request->validate()`（多数）が混在
- `lang/ja/validation.php` が存在するが一部のコントローラーでしか活用されていない
- フロントエンドのエラーステートが `Record<string, string[]>` / `Record<string, string>` / `string | null` と不統一
- フィールドレベルのエラー表示がある画面（Register）と無い画面（AnnouncementForm、SubmitItem）が混在

## 2. ルーティングガード

### 2.1 設計方針

| 原則 | 説明 |
|------|------|
| 認証ガード | 未認証 → `/login` にリダイレクト（元のURLを保持） |
| 認可ガード | 権限不足 → 403ページを表示 |
| 認証済みガード | ログイン済み → 認証ページ（login/register等）にアクセス不可 |
| ログイン後復帰 | ログイン成功後、リダイレクト前のURLに戻る |

### 2.2 実装内容

#### 2.2.1 `GuestRoute` コンポーネント新規作成

認証済みユーザーが認証ページにアクセスした場合、ロール別ダッシュボードにリダイレクトする。

**ファイル**: `src/resources/ts/components/GuestRoute.tsx`（新規）

```typescript
import { Navigate } from 'react-router-dom';
import { CircularProgress, Box } from '@mui/material';
import { useAuth } from '../contexts/AuthContext';

interface GuestRouteProps {
  children: React.ReactElement;
}

const GuestRoute: React.FC<GuestRouteProps> = ({ children }) => {
  const { isAuthenticated, loading, user } = useAuth();

  if (loading) {
    return (
      <Box sx={{ display: 'flex', justifyContent: 'center', alignItems: 'center', minHeight: '100vh' }}>
        <CircularProgress />
      </Box>
    );
  }

  if (isAuthenticated && user) {
    // ロールに応じてリダイレクト
    if (user.roles.some(r => r.name === 'admin')) {
      return <Navigate to="/admin" replace />;
    } else if (user.roles.some(r => r.name === 'seller')) {
      return <Navigate to="/seller" replace />;
    } else {
      return <Navigate to="/participant/home" replace />;
    }
  }

  return children;
};

export default GuestRoute;
```

#### 2.2.3 `PrivateRoute` の改修

権限不足時のリダイレクト先を `/` から `Forbidden` コンポーネントに変更する。

**ファイル**: `src/resources/ts/components/PrivateRoute.tsx`

```typescript
import { Navigate, useLocation } from 'react-router-dom';
import { CircularProgress, Box } from '@mui/material';
import { useAuth } from '../contexts/AuthContext';
import Forbidden from '../pages/Forbidden';

interface PrivateRouteProps {
  children: React.ReactElement;
  requiredRoles?: string[];
}

const PrivateRoute: React.FC<PrivateRouteProps> = ({ children, requiredRoles }) => {
  const { isAuthenticated, loading, hasRole } = useAuth();
  const location = useLocation();

  if (loading) {
    return (
      <Box sx={{ display: 'flex', justifyContent: 'center', alignItems: 'center', minHeight: '100vh' }}>
        <CircularProgress />
      </Box>
    );
  }

  if (!isAuthenticated) {
    // ログインしていない場合、現在のURLを保持してリダイレクト
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  if (requiredRoles && requiredRoles.length > 0) {
    const hasRequiredRole = requiredRoles.some(role => hasRole(role));
    if (!hasRequiredRole) {
      // 権限がない場合は403ページを表示
      return <Forbidden />;
    }
  }

  return children;
};

export default PrivateRoute;
```

#### 2.2.4 `Login.tsx` のリダイレクト先復帰対応

ログイン成功後、`location.state.from` があればそのURLに戻す。

**ファイル**: `src/resources/ts/pages/auth/Login.tsx`

変更箇所（`handleSubmit` 内）:

```typescript
import { useNavigate, useLocation } from 'react-router-dom';

export default function Login() {
  const navigate = useNavigate();
  const location = useLocation();
  const { login } = useAuth();
  // ...

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setError('');
    setLoading(true);

    try {
      await login(email, password);

      // リダイレクト元があればそこに戻る
      const from = (location.state as { from?: Location })?.from;
      if (from) {
        navigate(from.pathname + (from.search || ''), { replace: true });
        return;
      }

      // ロールに応じたデフォルトリダイレクト
      const userStr = localStorage.getItem('user');
      if (userStr) {
        const user = JSON.parse(userStr);
        if (user.roles?.some((r: any) => r.name === 'admin')) {
          navigate('/admin', { replace: true });
        } else if (user.roles?.some((r: any) => r.name === 'seller')) {
          navigate('/seller', { replace: true });
        } else {
          navigate('/participant/home', { replace: true });
        }
      }
    } catch (err: any) {
      setError(
        err.response?.data?.message || err.message || 'ログインに失敗しました'
      );
    } finally {
      setLoading(false);
    }
  };
```

## 3. 404統一

### 3.1 設計方針

| シナリオ | 処理 |
|---------|------|
| 未定義ルートへのアクセス | フロントエンド `NotFound` コンポーネント表示 |
| API が 404 を返した場合（詳細ページ等） | 各ページで `NotFound` コンポーネントを表示 |
| API が 404 を返した場合（一覧ページ等） | エラーメッセージを表示（現状維持） |

### 3.2 実装内容

#### 3.2.1 Laravel例外ハンドラーのカスタマイズ

API リクエストの例外を統一的なJSON形式で返す。

**ファイル**: `src/bootstrap/app.php`

```php
<?php

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Illuminate\Database\Eloquent\ModelNotFoundException;
use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        //
    })
    ->withExceptions(function (Exceptions $exceptions) {
        // API リクエストの 404 レスポンスを統一
        $exceptions->renderable(function (NotFoundHttpException $e, $request) {
            if ($request->is('api/*') || $request->wantsJson()) {
                $message = 'リソースが見つかりません。';

                // ModelNotFoundException の場合、モデル名からメッセージを生成
                $previous = $e->getPrevious();
                if ($previous instanceof ModelNotFoundException) {
                    $modelClass = class_basename($previous->getModel());
                    $modelNames = [
                        'Auction'      => 'オークション',
                        'Item'         => '商品',
                        'User'         => 'ユーザー',
                        'Announcement' => 'お知らせ',
                        'WonItem'      => '落札情報',
                        'Lane'         => 'レーン',
                    ];
                    $name = $modelNames[$modelClass] ?? $modelClass;
                    $message = "指定された{$name}が見つかりません。";
                }

                return response()->json([
                    'success' => false,
                    'message' => $message,
                    'error_code' => 'NOT_FOUND',
                ], 404);
            }
        });

        // API リクエストの 403 レスポンスを統一
        $exceptions->renderable(function (\Symfony\Component\HttpKernel\Exception\AccessDeniedHttpException $e, $request) {
            if ($request->is('api/*') || $request->wantsJson()) {
                return response()->json([
                    'success' => false,
                    'message' => 'この操作を行う権限がありません。',
                    'error_code' => 'FORBIDDEN',
                ], 403);
            }
        });
    })
    ->create();
```

#### 3.2.3 フロントエンド共通エラーフック新規作成

各ページで404/403を簡単にハンドリングできるカスタムフック。

**ファイル**: `src/resources/ts/hooks/useApiError.ts`（新規）

```typescript
import { useState, useCallback } from 'react';

interface ApiErrorState {
  status: number | null;
  message: string;
}

export function useApiError() {
  const [apiError, setApiError] = useState<ApiErrorState | null>(null);

  const handleApiError = useCallback((error: any) => {
    const status = error?.response?.status || null;
    const message = error?.response?.data?.message
      || error?.message
      || '予期しないエラーが発生しました。';

    setApiError({ status, message });
  }, []);

  const clearError = useCallback(() => {
    setApiError(null);
  }, []);

  const isNotFound = apiError?.status === 404;
  const isForbidden = apiError?.status === 403;

  return {
    apiError,
    handleApiError,
    clearError,
    isNotFound,
    isForbidden,
  };
}
```

## 4. バリデーションメッセージ統一

### 4.1 設計方針

| 原則 | 説明 |
|------|------|

#### 4.2.4 バリデーションエラーレスポンス形式の統一

全APIで以下の形式に統一する（Laravel の `FormRequest` デフォルト動作）:

```json
{
  "success": false,
  "message": "入力内容に誤りがあります。",
  "errors": {
    "title": ["タイトルは必須です。"],
    "content": ["本文は必須です。"]
  }
}
```

`FormRequest` のデフォルト `failedValidation` をオーバーライドし、`success: false` を含める。

**ファイル**: `src/app/Http/Requests/BaseFormRequest.php`（新規）

```php
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Contracts\Validation\Validator;
use Illuminate\Http\Exceptions\HttpResponseException;

abstract class BaseFormRequest extends FormRequest
{
    protected function failedValidation(Validator $validator)
    {
        throw new HttpResponseException(
            response()->json([
                'success' => false,
                'message' => '入力内容に誤りがあります。',
                'errors'  => $validator->errors(),
            ], 422)
        );
    }
}
```

全 FormRequest クラスは `BaseFormRequest` を継承する。

#### 4.3.2 フォームエラーハンドリングフック

**ファイル**: `src/resources/ts/hooks/useFormErrors.ts`（新規）

```typescript
import { useState, useCallback } from 'react';
import type { ValidationErrors } from '../types';

export function useFormErrors() {
  const [errors, setErrors] = useState<ValidationErrors>({});
  const [generalError, setGeneralError] = useState<string>('');

  /** API の catch で呼び出す */
  const handleValidationError = useCallback((error: any) => {
    const response = error?.response;

    if (response?.status === 422 && response?.data?.errors) {
      // フィールドレベルエラー
      setErrors(response.data.errors);
      setGeneralError(response.data.message || '入力内容に誤りがあります。');
    } else {
      // その他のエラー
      setErrors({});
      setGeneralError(
        response?.data?.message || error?.message || '予期しないエラーが発生しました。'
      );
    }
  }, []);

  /** 特定フィールドの最初のエラーメッセージを取得 */
  const getFieldError = useCallback(
    (field: string): string | undefined => errors[field]?.[0],
    [errors]
  );

  /** 特定フィールドにエラーがあるか */
  const hasFieldError = useCallback(
    (field: string): boolean => !!errors[field]?.length,
    [errors]
  );

  /** エラーをクリア */
  const clearErrors = useCallback(() => {
    setErrors({});
    setGeneralError('');
  }, []);

  /** 特定フィールドのエラーをクリア */
  const clearFieldError = useCallback((field: string) => {
    setErrors(prev => {
      const next = { ...prev };
      delete next[field];
      return next;
    });
  }, []);

  return {
    errors,
    generalError,
    handleValidationError,
    getFieldError,
    hasFieldError,
    clearErrors,
    clearFieldError,
  };
}
```

#### 4.3.3 フォームでの使用例

```typescript
import { useFormErrors } from '../../hooks/useFormErrors';

export default function AnnouncementForm() {
  const {
    generalError,
    handleValidationError,
    getFieldError,
    hasFieldError,
    clearFieldError,
    clearErrors,
  } = useFormErrors();

  const handleSubmit = async () => {
    clearErrors();
    try {
      await axios.post('/api/admin/announcements', formData);
      navigate('/admin/announcements');
    } catch (err) {
      handleValidationError(err);
    }
  };

  return (
    <>
      {generalError && <Alert severity="error" sx={{ mb: 2 }}>{generalError}</Alert>}

      <TextField
        label="タイトル"
        value={formData.title}
        onChange={(e) => {
          setFormData({ ...formData, title: e.target.value });
          clearFieldError('title');
        }}
        error={hasFieldError('title')}
        helperText={getFieldError('title')}
        required
      />

      <TextField
        label="本文"
        value={formData.content}
        onChange={(e) => {
          setFormData({ ...formData, content: e.target.value });
          clearFieldError('content');
        }}
        error={hasFieldError('content')}
        helperText={getFieldError('content')}
        multiline
        rows={6}
        required
      />
    </>
  );
}
```
