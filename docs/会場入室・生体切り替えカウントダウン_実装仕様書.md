# 会場入室・生体切り替えカウントダウン 実装仕様書

## 1. 概要

本仕様書は、以下の2機能の要件・設計・実装方針を定義する。

1. **会場入室時刻の制御**  
   オークション開始時刻の一定時間前から参加者がオークション会場（待機室）に入室できるようにする。
2. **生体切り替え時の入札開始待機**  
   レーンで次の生体に切り替わった際、入札が開始するまで一定時間のカウントダウンを設け、参加者が生体を確認してから入札できるようにする。

---

## 2. 用語定義

| 用語 | 説明 |
|------|------|
| オークション会場 | 参加者がライブオークションに参加する画面（URL: `/participant/auctions/:id/live`）。待機室・ライブ本編・終了画面を含む。 |
| 入室 | 参加者がオークション会場URLにアクセスし、待機室またはライブ画面を表示できる状態になること。 |
| 入室可能時刻 | 参加者が初めて会場に入室できる日時。＝ オークション開始予定日時 − 入室可能分数。 |
| 生体切り替え | レーンで現在の生体が落札/流札となり、次の生体が表示されること。 |
| 入札開始待機 | 生体切り替え後、新生体を表示した状態で「入札開始まで○秒」と表示し、その間は入札を受け付けない状態。 |
| 入札カウントダウン | 既存の「価格上昇までのカウントダウン」または「落札判定までのカウントダウン」を指す。 |

---

## 3. 機能1: 会場入室時刻の制御

### 3.1 目的

- オークション開始の**30分前**（デフォルト）から参加者が会場に入室できるようにする。
- 開始時刻より前は「開始まで待機」のメッセージのみ表示し、30分前を過ぎたら待機室（会場）に入室できるようにする。

### 3.2 要件

#### 3.2.1 入室可否の判定

- **入室可能となる条件（すべて満たすこと）**
  - オークションの `status` が `scheduled` であること。
  - 現在日時が **入室可能時刻** 以降であること。  
    - 入室可能時刻 ＝ `event_date` と `start_time` から算出した「開始予定日時」− **入室可能分数**（分）。
- **入室不可の場合**
  - 上記のいずれかを満たさない場合（例: 開始40分前で入室可能が30分の場合）は、会場URLにアクセスしても入室させず、**「オークション開始○分前から入室できます」** などのメッセージを表示する。

#### 3.2.2 入室可能分数の設定

- **システム設定（デフォルト）**
  - キー: `venue_open_minutes_before_start`
  - 意味: オークション開始何分前から入室可能にするか。
  - デフォルト値: **30**（分）。
  - 単位: 分。整数。1〜120 を推奨（運用で変更可能）。
- **オークションごとの設定（オプション）**
  - オークションのカスタム設定（`custom_auction_settings` または同等）に `venue_open_minutes_before_start` を保持可能とする。
  - オークションで値を設定している場合はその値を使用し、未設定の場合はシステム設定のデフォルトを使用する。
- **取得優先順位**  
  `オークションのカスタム設定` > `システム設定のデフォルト`（既存の getAuctionSettings のマージルールに合わせる）。

### 3.3 画面・API挙動

#### 3.3.1 参加者向けライブ会場API（`GET /api/participant/auctions/:id/live`）

- **オークションが `scheduled` の場合**
  - 現在日時 < 入室可能時刻  
    - HTTP 200 で、`data` に `entrance_allowed: false` および `entrance_at`（入室可能になる日時 ISO8601）および `message`（例: 「オークション開始30分前から入室できます」）を返す。  
    - フロントはこのレスポンスに基づき、会場ではなく「○分前から入室できます」画面を表示する。
  - 現在日時 >= 入室可能時刻  
    - 現行どおり、`status: 'scheduled'` で待機室用のデータ（`lanes: []` 等）を返す。  
    - `data` に `entrance_allowed: true` を追加してもよい（フロントの分岐が明確になる）。
- **オークションが `live` / `finished` の場合**
  - 現行どおり。入室可能時刻の判定は不要（すでに開始後または終了後）。

#### 3.3.2 参加者向けフロント（オークション会場ページ）

- `entrance_allowed === false` のとき
  - 待機室ではなく、次のような専用画面を表示する。
    - 文言例: 「オークション開始○分前から入室できます」
    - 入室可能時刻の表示（例: 「入室可能: 2026年2月10日 9:30」）
    - オークション名・開始時刻の表示
  - 自動リフレッシュ（例: 1分ごと）で入室可能になったら待機室に切り替えてもよい。
- `entrance_allowed === true` かつ `status === 'scheduled'` のとき
  - 現行の「待機室」画面を表示する。

### 3.4 データ定義・設定項目

#### 3.4.1 システム設定（system_settings）

| setting_key | 説明 | value_type | デフォルト | 備考 |
|-------------|------|------------|------------|------|
| venue_open_minutes_before_start | 開始何分前から入室可能にするか | integer | 30 | 1〜120 推奨 |

#### 3.4.2 オークション設定（オークションごと）

- 既存の「オークション設定」のカスタム設定に以下を追加する。
- キー: `venue_open_minutes_before_start`
- 型: 整数（分）
- 未設定の場合はシステム設定の値を使用する（getAuctionSettings のマージで反映）。

#### 3.4.3 開始予定日時の算出

- `start_datetime = Carbon::parse($auction->event_date->format('Y-m-d') . ' ' . $auction->start_time)` などで「開始予定日時」を算出する。
- 入室可能時刻 = `start_datetime->copy()->subMinutes($minutes)`。

## 4. 機能2: 生体切り替え時の入札開始待機（カウントダウン）

### 4.1 目的

- レーンで次の生体に切り替わった直後に、すぐに入札カウントダウンが始まると流れが早く、参加者が生体を確認しづらい。
- そのため、**生体切り替え後、新生体を表示した状態で「入札開始まで○秒」のカウントダウンを行い、その間は入札を受け付けない**ようにする。
- カウントダウン終了後に、既存の入札カウントダウン（価格上昇/落札判定用）を開始する。

### 4.2 要件

#### 4.2.1 流れ（レーン1本のイメージ）

1. 現在の生体でカウントダウン終了（落札 or 流札）。
2. 次の生体がレーンに表示される（`LaneItemChanged` ブロードキャスト）。
3. **入札開始待機フェーズ**
   - 画面表示: 新生体の情報 ＋ 「入札開始まで ○ 秒」のカウントダウン。
   - この間は入札ON/OFFボタンは無効または非表示。価格は開始価格のまま。
4. 待機秒数が 0 になったら **入札開始**。
   - 既存の入札カウントダウン（countdown_seconds）を開始する。
   - 入札ON/OFFが有効になる。

#### 4.2.2 待機秒数の設定

- **システム設定（デフォルト）**
  - キー: `item_switch_delay_seconds`
  - 意味: 生体切り替え後、入札を開始するまで何秒待つか。
  - デフォルト値: **5**（秒）。0 の場合は待機なし（現行挙動に近い）。
  - 単位: 秒。整数。0〜60 を推奨。
- **オークションごとの設定**
  - オークションのカスタム設定に `item_switch_delay_seconds` を保持可能とする。
  - オークションで値を設定している場合はその値、未設定の場合はシステム設定のデフォルトを使用する。
- **取得**  
  既存の `getAuctionSettings()` のマージ結果から取得する（Auction モデル経由）。

### 4.3 状態設計（レーン単位）

- レーンには次の2種類の「カウントダウン状態」があるものとして扱う。
  1. **入札開始待機中**（新規）  
     - 表示用: 「入札開始まで X 秒」
     - この間は入札不可。カウントダウンジョブでは「入札開始待機」用のティックのみ行い、価格上昇・落札判定は行わない。
  2. **入札カウントダウン中**（既存）  
     - 表示用: 「残り X 秒」（既存）
     - 入札可。既存ロジックどおり価格上昇・落札判定あり。

- キャッシュまたは状態の持ち方の例:
  - 例: `countdown:lane:{lane_id}` に `phase: 'pre_bid' | 'bidding'` を追加する。
  - `pre_bid` の間は `remaining_seconds` を減らすだけ。0 になったら `phase` を `bidding` にし、既存の入札カウントダウンを開始する。

### 4.4 バックエンド挙動

#### 4.4.1 CountdownService / moveToNextItem

- 次の生体に切り替える処理（`moveToNextItem` 相当）で:
  - 次のアイテムを `current_item_id` に設定し、`status: 'live'` にする。
  - **すぐには** `startCountdown`（既存の入札カウントダウン）を呼ばない。
  - 代わりに **入札開始待機フェーズ** を開始する:
    - 取得した `item_switch_delay_seconds`（0 の場合は待機なしで即 `startCountdown`）で、レーン用の「入札開始待機」状態をキャッシュに書き、待機用のカウントダウンを開始する。
  - `LaneItemChanged` のブロードキャストには、クライアントが「入札開始待機」を表示するために必要な情報を含める:
    - 例: `pre_bid_countdown_seconds`, `pre_bid_remaining_seconds`（または `phase: 'pre_bid'` と remaining）。

#### 4.4.2 カウントダウンジョブ（ProcessCountdownJob 等）

- 毎秒のティックで、対象レーンが「入札開始待機中」か「入札カウントダウン中」かを判定する。
- **入札開始待機中**
  - `remaining_seconds` を 1 減らす。
  - クライアントへ「入札開始まで X 秒」をブロードキャスト（既存の CountdownTick を流用するか、専用イベントを追加する）。
  - 0 になったら:
    - そのレーンの入札開始待機を終了し、**既存の startCountdown（入札カウントダウン）を開始**する。
- **入札カウントダウン中**
  - 既存どおり価格上昇・落札判定のロジックを実行する。

#### 4.4.3 入札API（参加者の入札ON/OFF）

- レーンが「入札開始待機中」のときは、そのレーンの現在アイテムへの入札ON/OFFを **拒否** する。
  - 例: HTTP 400 とメッセージ「入札開始までお待ちください」。

### 4.5 フロント（参加者・落札者用オークション画面）

- 各レーンカードで、現在のフェーズに応じて表示を切り替える。
  - **入札開始待機中**
    - 生体情報・サムネイル・現在価格（開始価格）を表示。
    - 「入札開始まで ○ 秒」を大きく表示。
    - 入札ON/OFFボタンは無効または非表示。
  - **入札カウントダウン中**
    - 既存どおり「残り X 秒」と入札ON/OFFボタンを表示。
- WebSocket（CountdownTick または新イベント）で `pre_bid_remaining_seconds` が届く場合は、それを使って表示を更新する。

### 4.6 データ定義・設定項目

#### 4.6.1 システム設定（system_settings）

| setting_key | 説明 | value_type | デフォルト | 備考 |
|-------------|------|------------|------------|------|
| item_switch_delay_seconds | 生体切り替え後、入札開始まで何秒待つか | integer | 5 | 0〜60 推奨。0 で待機なし。 |

#### 4.6.2 オークション設定（オークションごと）

- カスタム設定に `item_switch_delay_seconds`（整数・秒）を追加。
- 未設定時はシステム設定の値を使用。

### 4.7 管理者画面での「手動で次の商品に進む」

- 管理者がライブコントロールで「次の商品に進む」を実行した場合も、**同じ「入札開始待機」を挟む**ものとする。
- 即座に入札カウントダウンが始まらないようにし、参加者体験を統一する。

## 5. 管理者画面・システム設定画面

### 5.1 システム設定（管理画面）

- **オークション** タブ（または「会場・レーン」など）に、以下を追加する。
  - **会場入室**
    - 「会場入室可能開始（開始何分前から）」  
      - 数値入力（分）、デフォルト 30。説明: 「オークション開始の何分前から参加者が会場（待機室）に入室できるか」
  - **生体切り替え**
    - 「生体切り替え後の入札開始待機（秒）」  
      - 数値入力（秒）、デフォルト 5。説明: 「レーンで次の生体に切り替わった後、入札を開始するまでの待機秒数。0 で待機なし」

### 5.2 オークション編集・作成画面（管理画面）

- オークションの「オークション設定」に、以下を任意項目として追加する。
  - **会場入室可能開始（分）**  
    - 未入力の場合はシステム設定のデフォルトを使用する旨を表示。
  - **生体切り替え後の入札開始待機（秒）**  
    - 未入力の場合はシステム設定のデフォルトを使用する旨を表示。
- 既存の「カウントダウン秒数」等と同様、カスタム設定を使用する場合はここで上書きする。

## 6. API 仕様（追加・変更）

### 6.1 GET /api/participant/auctions/:id/live（変更）

- オークションが `scheduled` のとき、入室可能時刻を判定し、レスポンスに以下を追加する。
  - `entrance_allowed` (boolean): 入室してよいか。
  - `entrance_at` (string, ISO8601): 入室可能になる日時。入室不可の場合にのみ必須でも可。
  - `venue_open_minutes_before_start` (integer): 使用している入室可能分数（表示用）。
  - `message` (string): 入室不可時のメッセージ（例: 「オークション開始30分前から入室できます」）。

### 6.2 ライブ状態・WebSocket イベント（生体切り替え）

- `LaneItemChanged` のペイロードに、入札開始待機用の情報を追加する。
  - 例: `pre_bid_countdown_seconds`, `pre_bid_remaining_seconds`（または `phase: 'pre_bid'`）。
- 入札開始待機のティック用に、既存の `CountdownTick` に `phase` を足すか、別イベント（例: `PreBidCountdownTick`）を用意する。
- `getLiveState` および参加者向けライブAPIの「レーン・現在アイテム」で、`pre_bid_remaining_seconds` など現在の待機残り秒数を返す。

## 7. データベース・マイグレーション

### 7.1 システム設定の追加

- `system_settings` に以下を insert するマイグレーションを追加する。
  - `venue_open_minutes_before_start`: 30（integer）
  - `item_switch_delay_seconds`: 5（integer）

### 7.2 オークション側

- オークションの「カスタム設定」は既存の `custom_auction_settings`（JSON）で保持するため、**新規カラムは不要**。
- `getAuctionSettings()` およびシステム設定のデフォルト取得で、上記2キーをマージして返すようにする。

## 8. 非機能要件・注意事項

- **タイムゾーン**  
  入室可能時刻の算出は、アプリケーションのデフォルトタイムゾーン（日本時間推奨）で統一する。
- **既存オークション**  
  既存のオークションは、オークションごとの設定がなければシステム設定のデフォルト（30分前入室・5秒待機）が適用される。
- **0 秒設定**  
  `item_switch_delay_seconds` が 0 の場合は、生体切り替え後すぐに既存の入札カウントダウンを開始する（現行に近い挙動）。
- **オークション開始時**  
  オークション開始時（最初の生体が各レーンに表示されるとき）に、同じ「入札開始待機」を挟むかは別途検討可能。本仕様では「生体切り替え時」を主対象とし、開始時は現行どおり即入札開始でもよい。
