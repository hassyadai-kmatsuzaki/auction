## 1. 機能概要

参加者が「この価格を超えたら入札を自動的にオフにする」という**上限値（指値）**を事前または競り中に設定できる機能。

価格上昇が自分の上限に達した瞬間に自動で入札オフになるため、意図せず上限を超えて落札するリスクを防ぐ。

### 機能の流れ

```
参加者
  │
  ├── オークション開始前
  │     └── 指値を設定（開始価格ベースのクイック入力 or カスタム入力）
  │
  └── オークション中
        ├── 指値を設定・変更（現在価格ベースのクイック入力 or カスタム入力）
        └── 価格が指値に達する → 自動で入札オフ → 参加者に通知
```

---

## 2. 用語定義

| 用語 | 説明 |
|------|------|
| **指値（上限値）** | 参加者が商品ごとに設定する「ここまでなら入札する」という上限価格 |
| **クイック入力** | 基準価格の倍率（1.5倍・2倍・2.5倍・3倍）を選ぶだけの簡易設定 |
| **カスタム入力** | 任意の金額を直接入力する設定 |
| **基準価格（開始前）** | 商品の「開始価格（start_price）」 |
| **基準価格（競り中）** | 指値ボタンを押下した時点の「現在価格（current_price）」 |
| **自動入札オフ** | 現在価格が指値に達した時点でシステムが自動的に入札を離脱する処理 |
| **セーフティ発動** | 自動入札オフが実行されたことを指す通称 |

## 3. ユーザーストーリー

### Story 1: オークション開始前に指値を設定する

> 参加者として、オークションが始まる前に各商品の上限価格を設定しておき、
> その価格を超えたら自動で入札がオフになるようにしたい。
> 落札時に予算を超えることへの不安を解消したい。

**受け入れ条件:**
- 出品一覧（AuctionItems）画面で商品ごとに指値を設定できる
- 開始価格の1.5倍・2倍・2.5倍・3倍のクイック選択ができる
- 任意の金額を手入力できる（カスタム入力）
- 設定した指値は画面に表示される（例: 「上限: ¥5,000」）
- オークション開始後、設定した指値が引き継がれる

---

### Story 2: オークション中に指値を設定・変更する

> 参加者として、競り中でも上限価格を設定・変更したい。
> 現在の価格を見ながら「あとこれくらいなら出せる」と判断して設定したい。

**受け入れ条件:**
- ライブ画面（AuctionLive）で各レーンに指値ボタンが表示される
- ボタン押下時の現在価格を基準にクイック入力（1.5倍・2倍・2.5倍・3倍）できる
- 任意金額のカスタム入力もできる
- 設定中の指値が画面に表示される（例: 「上限: ¥8,000」）
- 指値を削除（解除）することもできる

---

### Story 3: 価格が指値を超えたら自動で入札オフになる

> 参加者として、設定した上限価格に価格が達したら、
> 自動的に入札がオフになり予算オーバーを防いでほしい。
> また、自動オフになったことを知りたい。

**受け入れ条件:**
- 現在価格 ≥ 指値 になった瞬間に自動で入札が離脱される
- 画面上にスナックバーで通知が表示される（「¥X,XXX に達したため自動的に入札オフになりました」）
- 自動オフになった後も指値設定は残る（再入札時に再度確認できる）
- 自動オフ後に指値を変更すれば再入札できる

---

## 4. 機能仕様詳細

### 4-1. 指値の設定タイミング

| タイミング | 場所 | 基準価格 |
|-----------|------|---------|
| **オークション開始前** | 出品一覧画面（AuctionItems.tsx） | 商品の開始価格（start_price） |
| **オークション中（入札前）** | ライブ画面（AuctionLive.tsx） | 指値ボタン押下時の現在価格（current_price） |
| **オークション中（入札中）** | ライブ画面（AuctionLive.tsx） | 指値ボタン押下時の現在価格（current_price） |

### 4-2. 指値の有効範囲

- 指値は **商品（item_id）× 参加者（user_id）** の組み合わせで保持
- 一商品につき1つの指値を設定可能（上書き可）
- 指値は **0以上** の整数
- 指値を `0` または `null` にすると「未設定（セーフティなし）」とみなす

### 4-3. 指値の永続化

- 指値はDBに保存する（`bid_limit_prices` テーブル）
- オークション終了後も参照可能（精算・履歴確認用）

### 4-4. 自動入札オフの発動条件

```
現在価格（current_price）≥ 指値（limit_price）
  ↓ 且つ
参加者の入札状態が 'active'
  ↓
自動でLeaveBidActionを実行
  ↓
参加者にWebSocketで通知
```

## 5. 入力方式

### 5-1. クイック入力（開始前）

基準価格 = **商品の開始価格（start_price）**

| ボタン | 計算式 | 例（開始価格 ¥3,000） |
|--------|--------|---------------------|
| ×1.5   | start_price × 1.5 | ¥4,500 |
| ×2     | start_price × 2   | ¥6,000 |
| ×2.5   | start_price × 2.5 | ¥7,500 |
| ×3     | start_price × 3   | ¥9,000 |

### 5-2. クイック入力（競り中）

基準価格 = **指値ボタンを押した瞬間の現在価格（current_price）**

| ボタン | 計算式 | 例（現在価格 ¥5,000） |
|--------|--------|---------------------|
| ×1.5   | current_price × 1.5 | ¥7,500 |
| ×2     | current_price × 2   | ¥10,000 |
| ×2.5   | current_price × 2.5 | ¥12,500 |
| ×3     | current_price × 3   | ¥15,000 |

> **補足**: 競り中のクイック入力は「今の価格からどれだけ上乗せを許容するか」のイメージ。

### 5-3. カスタム入力

- テキストフィールドに直接金額を入力
- 入力値のバリデーション:
  - 数値のみ（整数）
  - 1以上の値
  - 現在価格以下の値は警告表示（設定は可能だが、即時発動する旨を警告）

## 6. 自動入札オフのロジック

### 6-1. チェックタイミング

以下のタイミングで「現在価格 ≥ 指値」をチェックし、条件を満たす場合は自動オフを実行する。

| チェックタイミング | 処理 |
|------------------|------|
| **価格上昇イベント時**（CountdownService::handlePriceIncrement） | 価格更新後に全アクティブ入札者の指値をチェック |
| **指値設定時**（SetBidLimitAction） | 設定した指値が現在価格以下なら即時発動を警告 |
| **入札ON時**（JoinBidAction） | 参加者が入札ONにした時点で現在価格 ≥ 指値なら入札を拒否 |

### 6-2. 自動オフの処理フロー

```php
// 価格上昇後のチェック（CountdownService内）
foreach (BidParticipant::forItem($item->id)->active()->get() as $participant) {
    $limit = BidLimitPrice::forItem($item->id)->forUser($participant->user_id)->first();
    if ($limit && $item->current_price >= $limit->limit_price) {
        // 自動離脱
        $leaveBidAction->execute($item, $participant->user_id);

        // 本人にWebSocket通知
        broadcast(new BidLimitReached(
            $auction->id,
            $lane->id,
            $item->id,
            $participant->user_id,
            $item->current_price,
            $limit->limit_price
        ));
    }
}
```

### 6-3. 通知イベント（WebSocket）

**イベント名:** `BidLimitReached`

**ペイロード:**
```json
{
  "lane_id": 1,
  "item_id": 101,
  "user_id": 42,
  "current_price": 8000,
  "limit_price": 7500,
  "message": "¥7,500 の上限に達したため、自動的に入札オフになりました"
}
```

## 7. データベース設計

### 7-1. 新規テーブル: `bid_limit_prices`

```sql
CREATE TABLE bid_limit_prices (
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    item_id       BIGINT UNSIGNED NOT NULL,
    user_id       BIGINT UNSIGNED NOT NULL,
    limit_price   DECIMAL(12, 2) NOT NULL COMMENT '上限価格（指値）',
    is_triggered  BOOLEAN NOT NULL DEFAULT FALSE COMMENT '自動オフが発動したか',
    triggered_at  TIMESTAMP NULL COMMENT '発動日時',
    created_at    TIMESTAMP NULL,
    updated_at    TIMESTAMP NULL,

    UNIQUE KEY uq_item_user (item_id, user_id),
    FOREIGN KEY (item_id) REFERENCES items(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX idx_item_id (item_id),
    INDEX idx_user_id (user_id)
);
```

### 7-2. カラム説明

| カラム | 型 | 説明 |
|-------|---|------|
| `item_id` | BIGINT | 対象商品ID |
| `user_id` | BIGINT | 参加者ID |
| `limit_price` | DECIMAL(12,2) | 設定された上限価格 |
| `is_triggered` | BOOLEAN | セーフティが発動したかどうか |
| `triggered_at` | TIMESTAMP | 発動した日時（ログ用） |

### 10-2. `useBidLimit.ts` の設計

```typescript
export function useBidLimit(itemId: number) {
  const queryClient = useQueryClient();

  // 現在の指値を取得
  const { data } = useQuery({
    queryKey: ['bid-limit', itemId],
    queryFn: () => bidLimitApi.get(itemId),
    staleTime: 30_000,
  });

  // 指値設定
  const setMutation = useMutation({
    mutationFn: (limitPrice: number) => bidLimitApi.set(itemId, limitPrice),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['bid-limit', itemId] }),
  });

  // 指値解除
  const removeMutation = useMutation({
    mutationFn: () => bidLimitApi.remove(itemId),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['bid-limit', itemId] }),
  });

  return {
    limitPrice: data?.limit_price ?? null,
    isTriggered: data?.is_triggered ?? false,
    setLimit: setMutation.mutate,
    removeLimit: removeMutation.mutate,
    isSetting: setMutation.isPending,
  };
}
```

### 11-2. `SetBidLimitAction.php` の設計

```php
class SetBidLimitAction
{
    public function execute(Item $item, int $userId, float $limitPrice): BidResultDto
    {
        // 指値を保存（upsert）
        BidLimitPrice::updateOrCreate(
            ['item_id' => $item->id, 'user_id' => $userId],
            ['limit_price' => $limitPrice, 'is_triggered' => false, 'triggered_at' => null]
        );

        // 現在価格が既に指値を超えている場合は即時発動
        if ($item->status === 'live' && $item->current_price >= $limitPrice) {
            $participant = BidParticipant::forItem($item->id)->forUser($userId)->first();
            if ($participant && $participant->is_active) {
                app(LeaveBidAction::class)->execute($item, $userId);
                // is_triggered を記録
                BidLimitPrice::forItem($item->id)->forUser($userId)
                    ->update(['is_triggered' => true, 'triggered_at' => now()]);

                return BidResultDto::success('上限価格を設定しました（現在価格が上限に達しているため即時入札オフになりました）', [
                    'limit_price' => $limitPrice,
                    'triggered'   => true,
                ]);
            }
        }

        return BidResultDto::success('上限価格を設定しました', [
            'limit_price' => $limitPrice,
            'triggered'   => false,
        ]);
    }
}
```

### 11-3. CountdownService への指値チェック追加箇所

```php
// handlePriceIncrement() の価格更新後に追加
protected function checkBidLimits(Item $item, Auction $auction, Lane $lane): void
{
    $activeBidders = BidParticipant::forItem($item->id)->active()->get();

    foreach ($activeBidders as $participant) {
        $limit = BidLimitPrice::where('item_id', $item->id)
            ->where('user_id', $participant->user_id)
            ->where('is_triggered', false)
            ->first();

        if ($limit && $item->current_price >= $limit->limit_price) {
            // 自動離脱
            app(LeaveBidAction::class)->execute($item, $participant->user_id);

            // 発動記録
            $limit->update(['is_triggered' => true, 'triggered_at' => now()]);

            // 本人にWebSocket通知
            broadcast(new BidLimitReached(
                $auction->id,
                $lane->id,
                $item->id,
                $participant->user_id,
                $item->current_price,
                $limit->limit_price
            ));
        }
    }
}
```

## 12. エッジケース・考慮事項

| ケース | 対応方針 |
|--------|---------|
| **現在価格 ≥ 指値 で設定した場合** | 設定は保存するが、入札中なら即時自動オフ。警告メッセージを表示。 |
| **指値と同額の場合** | `current_price >= limit_price`（以上）のため発動する |
| **価格上昇後に指値を下回った場合** | 自動オフ発動済みの場合は再入札しても新たに自動オフは走らない（`is_triggered = true` でスキップ）。再設定すればリセット。 |
| **複数レーンで同じ商品を入札している場合** | `item_id` + `user_id` で一意なため、指値は1つだけ |
| **商品が次の生体に変わった場合** | 新しい商品にはその商品の指値（なければ未設定）が適用される。前の商品の指値は引き継がない。 |
| **競り中に入れた指値が価格と逆転した場合** | 上記「現在価格 ≥ 指値」のケースに該当 |
| **0.5秒カウントダウン中のタイミング** | `handlePriceIncrement` 後にチェックするため、価格変更と同一トランザクション内で実行される。遅延なし。 |
| **ネットワーク切断中の通知** | WebSocketで通知できない場合は、再接続後の `fetchLiveState()` で `my_bid_status: inactive` を確認することで状態を把握できる。 |
