# セキュリティインシデント対応フロー

**文書番号**: INC-2026-001  
**版数**: 1.0  
**最終更新**: 2026年4月22日  
**対象システム**: メダカオークション

---

## 1. インシデント分類

| レベル | 定義 | 例 | 対応期限 |
|--------|------|-----|---------|
| Critical | サービス停止・データ漏洩 | DB侵害、大規模DDoS | 即座 |
| High | 機能障害・攻撃検知 | 不正ログイン多発、WAFブロック急増 | 1時間以内 |
| Medium | 部分的影響 | 一部API遅延、不審なアクセスパターン | 4時間以内 |
| Low | 潜在的リスク | 脆弱性報告、設定不備発見 | 24時間以内 |

## 2. 検知フェーズ

### 自動検知
- **CloudWatch アラーム**: WAFブロック数、エラーレート、レイテンシ異常
- **監査ログ**: `storage/logs/audit.log` の異常パターン
- **レート制限**: `RateLimitByIp` による429レスポンス急増
- **認証ログ**: ログイン失敗の集中発生

### 手動検知
- ユーザーからの報告
- 定期セキュリティレビュー
- 脆弱性診断結果

## 3. 初動対応フロー

```
[検知] → [レベル判定] → [エスカレーション] → [封じ込め] → [原因調査] → [復旧] → [事後対応]
```

### Step 1: 検知・レベル判定（5分以内）
1. アラート受信者がインシデントの概要を把握
2. インシデントレベルを判定
3. インシデント対応チケットを起票

### Step 2: エスカレーション
| レベル | 通知先 | 手段 |
|--------|--------|------|
| Critical | CTO + 開発チーム全員 | 電話 + Slack |
| High | 開発リーダー + 運用担当 | Slack |
| Medium | 運用担当 | Slack |
| Low | 担当者 | チケット |

### Step 3: 封じ込め（Critical/High は30分以内）

#### 不正アクセス検知時
```bash
# 疑わしいIPをWAFでブロック
aws wafv2 update-ip-set --name "block-list" --addresses "x.x.x.x/32"

# 該当ユーザーのセッション無効化
php artisan tinker --execute="User::find(ID)->tokens()->delete()"

# 該当ユーザーを一時停止
php artisan tinker --execute="User::find(ID)->update(['is_active' => false])"
```

#### DDoS攻撃時
```bash
# AWS Shield Advanced の DRT に連絡（有効時）
# WAF レート制限を強化
# CloudFront のキャッシュ設定を最適化
# 必要に応じてメンテナンスモードに切り替え
php artisan down --secret="emergency-access-token"
```

#### データ漏洩疑い時
```bash
# 全APIアクセストークンを無効化
php artisan tinker --execute="PersonalAccessToken::query()->delete()"

# DBアクセスログの確認
# 監査ログの保全（コピー取得）
cp storage/logs/audit*.log /secure-backup/
```

### Step 4: 原因調査

確認すべきログ:
1. **監査ログ**: `storage/logs/audit.log` — 誰が何をしたか
2. **アプリログ**: `storage/logs/laravel.log` — エラー・例外
3. **WAFログ**: AWS WAF ログ — ブロックされたリクエスト
4. **ALBアクセスログ**: S3 — 全リクエスト記録
5. **CloudTrail**: AWSリソースへの操作記録

### Step 5: 復旧
1. 根本原因の修正（コード修正、設定変更）
2. テスト環境での検証
3. 本番環境への適用
4. サービス正常動作の確認

### Step 6: 事後対応
1. **インシデントレポート作成**（発生後48時間以内）
   - 発生日時・検知日時
   - 影響範囲
   - 根本原因
   - 対応内容・タイムライン
   - 再発防止策
2. **振り返りミーティング**（発生後1週間以内）
3. **再発防止策の実施**（期限を設定）
4. **関係者への報告**（個人情報漏洩時は法的対応含む）
