## 1. TL;DR

**現在価格と同額の指値が2件以上並ぶと、後発者を脱落させる処理が実行されず、全員が「入札中」のままボタンが押せなくなる。** 最終的に商品は流札する（誰かが手動入札しない限り）。

原因は `adjustPriceByBidLimits()` の早期 return が「価格更新の要否」と「指値トリガー処理の要否」を分離できていないこと。**修正は1箇所（1関数内の実質2行）。**

2026-07-16 の E2E（item 2528）で再現し、ログで確定。第4回本番（2026-07-03）では**発火0件**だが、発火条件は実在する。

## 3. 期待される正しい挙動

開始価格1400、A（先設定・指値1400）、B（後設定・指値1400）の場合:

1. **A が最高入札者**（`created_at` の早い方が落札権利者 = 2026-05-15 の proxy-bid 仕様）
2. **B は離脱し、入札ボタンが押せる状態になる**
3. B が押さなければ → **A が 1400円で落札**
4. B が押せば → 価格 1500円、**B が最高入札者**

これは eBay 等の proxy 入札と同じ標準ルール。**本修正はこの挙動を実現する。**

## 4. 根本原因

`adjustPriceByBidLimits()`（`app/Services/CountdownService.php:1287`）の該当部分。

```php
L1327   $targetPrice = $currentPrice;                    // 1400

L1329   if ($highestLimit == $secondHighestLimit) {      // 1400 == 1400 → 同額タイ
L1332       $targetPrice = $highestLimit;                // → 1400（据え置き。跳ねる余地がない）
L1333       Log::info("same-price highest limits detected, ...");
        }

L1362   if ($targetPrice <= $currentPrice) {             // 1400 <= 1400 → true
L1363       DB::rollBack();                              // ★ ここで全部捨てられる
L1364       return;
        }

        // ───────── 以下に到達しない ─────────
L1396   $allTriggeredLimits = BidLimitPrice::where('item_id', $item->id)
L1397       ->where('is_triggered', false)
L1398       ->where(function ($q) use ($freshItem, $protectedUserIds) {
L1399           $q->where('limit_price', '<', $freshItem->current_price)
L1400             ->orWhere(function ($q2) use ($freshItem, $protectedUserIds) {
L1401                 $q2->where('limit_price', $freshItem->current_price)
L1402                    ->whereNotIn('user_id', $protectedUserIds);   // ← B を脱落させる条件
                    });
            });
```

**L1362 は「価格更新の要否」だけを判断すべき箇所だが、実際には「指値トリガー処理の要否」まで巻き添えで殺していた。**

同額タイ分岐（L1329）は「価格は最高指値のまま据え置く」ため `$targetPrice = $highestLimit` を代入する。ところが**現在価格が既にその同額と一致している**と `$targetPrice == $currentPrice` となり、L1362 に吸い込まれる。

### 発動条件

**「有効な指値の上位2件が同額 かつ その額が現在価格と一致」**

クエリが `limit_price >= $currentPrice` で絞っているため、最大値が現在価格と一致するということは**全ての有効指値が現在価格ちょうど**を意味する。すなわち:

- **2名以上が「現在価格ちょうど」の指値を持つ**
- **かつ、それより高い指値の人が1人もいない**

最も踏みやすいのは「開始価格ちょうどの指値が2件、他に高い指値なし」（= item 2528 のケース）。誰か1人でも高い指値を置いていれば `highest > second` となり正常経路に入る。

### テストカバレッジの穴

既存テスト `tests/Unit/Services/CountdownServiceTest.php:499`
`test_adjustPriceByBidLimits_は_同額指値で先設定者を保護してアクティブのまま残す` は、**開始価格 10000 / 指値 20000** でタイを作っている。`targetPrice(20000) > currentPrice(10000)` なので L1362 を通過してしまい、**「同額指値 == 現在価格」を一行もカバーしていなかった。**
