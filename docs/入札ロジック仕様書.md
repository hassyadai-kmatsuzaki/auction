## 1. フェーズとカウントダウン

1商品あたりの進行は必ず次のフェーズを通ります。各フェーズは `countdown:lane:{laneId}` のキャッシュ state.phase で管理されます。

```
┌──────────┐     ┌──────────┐    ┌──────────┐    ┌──────────┐
│ pre_bid  │ →  │ bidding  │ →  │ freeze   │ →  │ bidding  │ → … → 落札/流札
└──────────┘     └──────────┘    └──────────┘    └──────────┘
    入札待機      入札受付       価格上昇後の    入札受付
                                  誤タップ防止
```

| フェーズ | 役割 | 入札ボタン | 期間の根拠 |
|---------|-----|----------|-----------|
| `pre_bid` | 商品切替直後の待機。指値保持者は自動で入札ONに変換される | 無効 | `item_switch_delay_seconds` |
| `bidding` | 通常の入札受付。カウントダウン0到達で落札または価格上昇 | 有効 | `bid_countdown_seconds`（価格帯で可変） |
| `freeze` | 価格上昇直後の誤タップ防止。ボタン無効化 | 無効 | `freeze_countdown_seconds`（価格帯で可変） |

### フェーズ遷移（実装）

- `pre_bid → bidding`: [CountdownService.php:330-342](src/app/Services/CountdownService.php#L330-L342) `tickPreBid()` で remaining≤0 時
- `bidding → freeze`: 価格上昇（[handlePriceIncrement:472](src/app/Services/CountdownService.php#L472)）成功後
- `freeze → bidding`: [CountdownService.php:371-382](src/app/Services/CountdownService.php#L371-L382) `tickFreeze()` で remaining≤0 時
- `bidding → 落札/流札`: カウントダウン0到達 + active数=0/1（[L279-303](src/app/Services/CountdownService.php#L279-L303)）

## 2. 入札状態モデル

### 2.1 関係するテーブル

- **`bid_participants`**: 現在の入札ON/OFF状態（商品×ユーザーで1行、`is_active` 切替）
- **`bid_events`**: 入札アクションの不変ログ（join / leave / price_accept / win / lose）
- **`price_events`**: 価格変動の不変ログ（old_price, new_price, reason）
- **`bid_limit_prices`**: 指値（商品×ユーザーで1行）
- **`items.current_price`**: 現在価格の真実値
- **キャッシュ `countdown:lane:{laneId}`**: フェーズ、残り秒数、`last_bidder_user_id`

### 2.2 `last_bidder_user_id` の意味

「このレーンで **最後に入札ボタンを押した（= fresh join した）人**」を記録するキャッシュフィールド。

- 更新タイミング: [JoinBidAction.php:85](src/app/Actions/Bid/JoinBidAction.php#L85) で `$userId` をセット
- リセットタイミング: 価格上昇後（指値holderがいれば指値holder、いなければ `null`）— [CountdownService.php:479](src/app/Services/CountdownService.php#L479)

これが **通常入札時の落札権利者（holder）** になります。

## 3. 落札権利者（holder）の決定ルール

### 3.1 優先度（上から順に適用）

1. **指値保持者がいる場合** → **指値が最も高い人**（[CountdownService.php:420-442](src/app/Services/CountdownService.php#L420-L442)）
    - 同額指値なら `created_at ASC`（先に設定した人）
2. **指値保持者がいない場合** → **`last_bidder_user_id`**（最後に入札ボタンを押した人）
3. `last_bidder_user_id` が null の場合のフォールバック → **最新に activate したアクティブ参加者**（[L435](src/app/Services/CountdownService.php#L435) `orderBy('activated_at', 'desc')`）

### 3.2 具体例（通常入札のみ）

#### 例1: A → B の順に入札
```
時刻       価格   アクション            holder
10:00:00  100    A が ON              A (last_bidder=A)
10:00:02  100    B が ON              B (last_bidder=B に更新)
                 → 2人 → 即 handleImmediatePriceIncrement
                 → price_event 100→110
                 → 非holder (=A) を deactivate
                 → startFreeze
10:00:02  110    ← freeze 中、holder=B
10:00:05  110    (freeze 明け) bidding 開始
10:00:10  110    カウントダウン0 到達、active=1 → B が落札
```
**結果: B が¥110で落札**

#### 例2: B と C がほぼ同時（Bが1ms早い）
```
時刻          価格   アクション            holder
10:00:00     100    A が ON              A
10:00:00.50  100    B が ON              B ← 2人目 → 即価格上昇
                    → price_event 100→110, freeze
10:00:00.51  100    C が ON              ※ freeze 中なので拒否される
                    → 「誤タップ防止中」エラー
```
実際には 1ms 差でも、先に到達した B が先に **価格上昇 + freeze** を発動させるので、C は freeze に弾かれます。
→ **B が holder**

**ポイント**: freeze（誤タップ防止）があるため、「ほぼ同時」の2人目以降は2人目の処理が完了した瞬間ブロックされ、3人目以降は弾かれる仕組みです。

#### 例3: A が holder の状態で次の bidding で B が押す
```
時刻       価格   アクション                       holder
10:00:00  100    A が ON                         A
10:00:01  100    (誰か X が ON で価格上昇発生)    X → 即上昇
                 → 110円, freeze
10:00:04  110    freeze 明け、bidding 再開
10:00:05  110    B が ON                         B ← 2人目 → 即上昇
                 → 120円, freeze（B が holder）
```
→ **B が ¥120 の holder**

### 3.3 価格上昇時の参加者整理

価格が上昇するたびに [CountdownService.php:446-455](src/app/Services/CountdownService.php#L446-L455) で次の処理が走ります。

```
全アクティブ参加者をループ:
  - 指値保持者（protected）なら → 残す
  - そうでなく last_bidder ならば → 残す
  - それ以外は → deactivate() して bid_event='leave' を記録
```

つまり **価格上昇を跨ぐ瞬間に、holder以外は自動的に入札OFFにされる**。再度入札したければ freeze 明けに改めて ON を押す必要があります。

## 4. 価格上昇トリガーと刻み幅

### 4.1 上昇が発動する3パターン

| # | トリガー | 場所 |
|---|---------|------|
| A | **入札ONで active が 2人以上になった瞬間**（即時上昇） | [JoinBidAction.php:99-107](src/app/Actions/Bid/JoinBidAction.php#L99-L107) → `handleImmediatePriceIncrement()` |
| B | **bidding カウントダウン0到達時に active が 2人以上** | [CountdownService.php:279-290](src/app/Services/CountdownService.php#L279-L290) → `handlePriceIncrement()` |
| C | **有効な指値が2人以上になった時** | [SetBidLimitAction.php:96-102](src/app/Actions/Bid/SetBidLimitAction.php#L96-L102) → `adjustPriceByBidLimits()` |

### 4.2 刻み幅（金額帯別）

`auction->calculatePriceIncrement($currentPrice)` が価格帯別の刻みを返します。
設定は `system_settings.default_price_increment_tiers` または `auctions.custom_fee_settings.price_increment_tiers` で保持。

例（デフォルト設定例）:
| 現在価格 | 刻み |
|---------|------|
| 〜 ¥999 | ¥100 |
| ¥1,000〜¥9,999 | ¥500 |
| ¥10,000〜 | ¥1,000 |

### 4.3 連続上昇の禁止

価格上昇の直後は必ず `startFreezeCountdown()` が呼ばれるため、**freeze を経由せずに連続上昇することはありません**。

- [handlePriceIncrement:472](src/app/Services/CountdownService.php#L472) の呼び出し
- [handleImmediatePriceIncrement](src/app/Services/CountdownService.php#L541) 内でも最後に freeze を開始
- [adjustPriceByBidLimits](src/app/Services/CountdownService.php#L1078) の `$startFreeze=true` パス

また `handlePriceIncrement()` 冒頭で `$item->status !== 'live' || $activeBidderCount <= 1` のガードがあり、freeze 中やアクティブ1人以下では実行されません。

## 5. 指値（bid limit）の全挙動

### 5.1 ライフサイクル

```
┌──────────────────┐
│ 指値設定         │ SetBidLimitAction::execute()
└────────┬─────────┘
         │
         ├─ 商品が registered（未開始）
         │   └─ bid_limit_prices に保存のみ
         │      → オークション開始時 activatePendingBidLimits() で自動入札
         │
         ├─ 商品が live + 現在価格 < 指値
         │   ├─ BidParticipant を自動 ON
         │   └─ 他に指値がいる/入札者2人以上 → 価格上昇
         │
         └─ 商品が live + 現在価格 ≥ 指値
             └─ 即 is_triggered=true → bid_limit_prices から削除
                （入札中だったユーザーは自動で離脱）
```

### 5.2 指値複数時の価格計算 (`adjustPriceByBidLimits`)

有効な指値が**2人以上**存在する場合、価格を自動で跳ね上げます。

- **通常ケース（指値額が異なる）**: 最低指値の直上まで刻み幅で価格を引き上げる
  - ただし2番目に低い指値を超えない範囲
  - 例: 指値 ¥500 / ¥1,000 なら、current ¥100 から刻み ¥100 ずつ上げて **¥600** まで
- **同額ケース**: 価格は同額指値額に設定、**先に設定した方** が holder
- 発動した指値（`limit_price <= new_price` になったもの）は triggered にして削除

### 5.3 指値 vs 通常入札

| 状況 | holder になる人 |
|------|--------------|
| 指値 A(¥1,000) + 指値 B(¥800) | A（指値最高額） |
| 指値 A(¥1,000) + 通常入札 B | A（指値が優先） |
| 指値 A(¥500) + 通常入札 B + 通常入札 C | A が ¥500 到達まで残り、超えたら通常入札の last_bidder |
| 通常入札のみ A, B, C | `last_bidder_user_id`（最後に押した人） |

### 5.4 指値が発動して消える瞬間

- `is_triggered = true` に更新
- `bid_limit_prices` レコード削除（再入札をブロックしないため）
- そのユーザーが入札中なら自動で LeaveBidAction を実行
- `BidLimitReached` イベントをブロードキャスト（通知・UI反映）

## 6. 落札・流札の確定

### 6.1 bidding カウントダウン0到達時（[CountdownService.php:279-303](src/app/Services/CountdownService.php#L279-L303)）

```
active 参加者数 = 0 → 流札（status='unsold'）
active 参加者数 = 1 → 落札（status='sold', winner=その1名）
active 参加者数 ≥ 2 → 価格上昇（→ freeze）
```

### 6.2 落札時の処理（[FinalizeBidAction::finalizeAsSold](src/app/Actions/Bid/FinalizeBidAction.php#L47)）

1. `items.status = 'sold'`
2. `won_items` レコード作成（勝者ID / 価格 / 数量 / 手数料 / 支払期限等）
3. 勝者の登録住所を配送先にコピー（配送料は auction 終了時に一括計算）
4. `bid_events` に `win` / 他参加者全員に `lose` を記録
5. `ItemSold` ブロードキャスト
6. 落札通知（LINE / メール）送信

### 6.3 流札時の処理

- `items.status = 'unsold'`
- `won_items` は作成されない

## 7. 入札シナリオ早見表

### シナリオ A — 1人だけ入札
```
100  A ON  →  bidding 0到達, active=1
                → A が¥100で落札
```

### シナリオ B — 2人で奪い合い
```
100  A ON
100  B ON       → 即価格上昇 110, freeze, holder=B, A deactivate
110  (freeze)
110  A ON       → 即価格上昇 120, freeze, holder=A, B deactivate
120  (freeze)
120  bidding 0 到達, active=1 → A が¥120で落札
```

### シナリオ C — 指値 vs 通常
```
100  A ON
100  B 指値¥500設定 → 自動入札ON, 2人 → 価格上昇 110, freeze, holder=B (指値優先)
110  ... bidding でも A が押しても B が holder（指値が上回るため）
...
500  価格到達 → B の指値 triggered & 削除, B は自動leave
500  残り A のみ → A が¥500で落札
```
（実装: 指値が triggered になる瞬間に B は自動離脱するため、残りが A だけになれば次のカウントダウンで落札）

### シナリオ D — 指値2人
```
100  A 指値¥300, B 指値¥500 を同タイミングで設定
     → adjustPriceByBidLimits 発動, 価格→ ¥400（¥300の一つ上）
     → freeze, holder=B（指値が高い）
400  A の指値はまだ有効（400 < 指値¥300 で発動済み→削除）実際はA発動済み
...
```

### シナリオ E — 同額指値
```
100  A 指値¥500設定（先）
     B 指値¥500設定（後）
     → adjustPriceByBidLimits, target=500
     → holder = A（先に設定した方）
500  A が¥500で落札（B は triggered で離脱）
```

## 8. 不変条件（システム保証）

| # | 不変条件 | 根拠 |

| 1 | freeze中は入札不可 | [JoinBidAction.php:50-55](src/app/Actions/Bid/JoinBidAction.php#L50) |
| 2 | pre_bid中は入札不可 | [JoinBidAction.php:44-49](src/app/Actions/Bid/JoinBidAction.php#L44) |
| 3 | 現在価格 ≥ 指値の状態では新規入札不可 | [JoinBidAction.php:61-67](src/app/Actions/Bid/JoinBidAction.php#L61) |

| 5 | 価格上昇後は必ず freeze に入る | [CountdownService.php:472](src/app/Services/CountdownService.php#L472) |
| 6 | 価格上昇中（トランザクション中）に active が1人以下になれば no-op | [CountdownService.php:396](src/app/Services/CountdownService.php#L396) |
| 6-a | 価格更新は `items` 行の `lockForUpdate()` で排他化され、並行呼び出しでも二重上昇しない | [CountdownService.php:407](src/app/Services/CountdownService.php#L407), [CountdownService.php:915](src/app/Services/CountdownService.php#L915) |

| 10 | `price_events` は item の全価格遷移を網羅的に記録（監査可能） | 各価格更新と一緒に insert |
| 11 | `bid_events` は全入札アクションを不変記録 | join/leave/price_accept/auto_raise/win/lose すべて記録 |
